# 第五章 二叉树 参考答案

## 1 由残缺的三种遍历序列还原二叉树

**还原步骤。** 三个序列均有 11 位。后序末位给出根 `A`；中序以 `A` 划分后，左右子树各有 5 个结点。

1. 左子树的后序为 `_ E F D B`，故根为 `B`。中序 `C B _ _ F` 表明 `B` 的左孩子为 `C`，右子树有 3 个结点。该右子树的先序、后序分别为 `D E _` 和 `E F D`，故根为 `D`，两个孩子依次为 `E`、`F`。
2. 右子树的先序为 `G H I _ K`，后序为 `_ J I H _`，故根为 `G`，其余结点全在左子树。依次结合中序 `_ J K I G` 可得：`G` 的左孩子为 `H`，`H` 的右孩子为 `I`，`I` 的左孩子为 `J`，`J` 的右孩子为 `K`。

**还原出的二叉树：**

```text
          A
        /   \
       B     G
      / \   /
     C   D H
        / \ \
       E   F I
            /
           J
            \
             K
```

**逐序验证：**

```text
先序：A B C D E F G H I J K
中序：C B E D F A H J K I G
后序：C E F D B K J I H G A
```

将这三个完整序列中原题留空的位置重新替换为 `_`，恰好得到题目给出的三个序列。

## 2 叶结点在三种遍历序列中的相对次序相同

采用对结点数 $n$ 的**数学归纳法**。

**基础情况：**

* 当 $n = 0$（空二叉树）时，前/中/后序序列均为空，命题平凡成立。
* 当 $n = 1$（只有一个结点 `A` 的二叉树）时，前/中/后序序列都只是 `A`，叶结点就是 `A`，相对位置显然相同。

**归纳假设：** 假设当结点数 $< n$（$n \ge 2$）时，对任意二叉树，叶结点在前/中/后序序列中的相对位置都相同。

**归纳步：** 考虑结点数为 $n$ 的二叉树 $T$，设根结点为 $r$，左子树 $T_L$（结点数 $n_1 < n$），右子树 $T_R$（结点数 $n_2 < n$，$n_1 + n_2 = n - 1$）。记 $T_L$ 的前/中/后序序列分别为 $L_{\text{pre}}, L_{\text{in}}, L_{\text{post}}$，$T_R$ 的类似记为 $R_{\text{pre}}, R_{\text{in}}, R_{\text{post}}$。则 $T$ 的三种序列为

$$
T_{\text{pre}} = r\,L_{\text{pre}}\,R_{\text{pre}},\qquad
T_{\text{in}} = L_{\text{in}}\,r\,R_{\text{in}},\qquad
T_{\text{post}} = L_{\text{post}}\,R_{\text{post}}\,r .
$$

由于 $n \ge 2$，根 $r$ 至少有一个孩子，不是叶结点，叶结点**仅来自** $T_L$ 和 $T_R$。

由归纳假设，$T_L$ 的叶结点在 $L_{\text{pre}}, L_{\text{in}}, L_{\text{post}}$ 中的相对位置相同；$T_R$ 的叶结点在 $R_{\text{pre}}, R_{\text{in}}, R_{\text{post}}$ 中的相对位置也相同。

在每种序列中 $L$ 段和 $R$ 段都是连续的子串，并且都是 $L$ 段在前、$R$ 段在后，所以三种序列中叶结点的出现顺序都等于"$T_L$ 的叶结点序列"后接"$T_R$ 的叶结点序列"。因此 $T$ 的叶结点在三种序列中的相对位置相同。归纳完成。$\blacksquare$

## 3 哈夫曼树与哈夫曼编码

### (1) 哈夫曼树有 199 个结点，求叶子结点数

哈夫曼树是**严格二叉树**（没有度为 1 的结点），只有度为 0（叶子）和度为 2（内部）的结点。设叶子数为 $n_0$，度为 2 的结点数为 $n_2$。

* 总结点数：$n_0 + n_2 = 199$。
* 每个内部结点恰有两条指向孩子的边，而全树的边数为结点数减一，因此 $2n_2 = 199 - 1 = 198$。

解得 $n_2 = 99$，$n_0 = 100$。**叶子结点数为 100。**

> 简化版：哈夫曼树每次合并两棵子树，新增 1 个内部结点。从 $n$ 个叶子出发共合并 $n-1$ 次，最终结点数 $= 2n - 1$。所以 $2n - 1 = 199 \Rightarrow n = 100$。

### (2) 设计哈夫曼编码

将 1 至 8 号字母的频率放大 100 倍便于构造：`{7, 19, 2, 6, 32, 3, 21, 10}`。

**构造过程**（每次取两个最小合并）：

| 步骤 | 队列状态 | 合并 |
| --- | --- | --- |
| 初始 | 2, 3, 6, 7, 10, 19, 21, 32 | — |
| 1 | 5, 6, 7, 10, 19, 21, 32 | 2 + 3 = 5 |
| 2 | 7, 10, 11, 19, 21, 32 | 5 + 6 = 11 |
| 3 | 11, 17, 19, 21, 32 | 7 + 10 = 17 |
| 4 | 19, 21, 28, 32 | 11 + 17 = 28 |
| 5 | 28, 32, 40 | 19 + 21 = 40 |
| 6 | 40, 60 | 28 + 32 = 60 |
| 7 | 100 | 40 + 60 = 100 |

**哈夫曼树**（左 0、右 1，圈号为字母编号）：

```text
                 (100)
               /       \
           (40)         (60)
          /    \       /    \
      ②(19)  ⑦(21)  ⑤(32)  (28)
                           /    \
                        (17)    (11)
                        /  \    /  \
                    ①(7) ⑧(10) ④(6) (5)
                                    /  \
                                 ③(2)  ⑥(3)
```

**哈夫曼编码表：**

| 字母 | 频率 | 哈夫曼编码 | 二进制编码 |
| :-: | :-: | :-: | :-: |
| 1 | 0.07 | `1100` | `000` |
| 2 | 0.19 | `00` | `001` |
| 3 | 0.02 | `11110` | `010` |
| 4 | 0.06 | `1110` | `011` |
| 5 | 0.32 | `10` | `100` |
| 6 | 0.03 | `11111` | `101` |
| 7 | 0.21 | `01` | `110` |
| 8 | 0.10 | `1101` | `111` |

> 哈夫曼编码不唯一（左右子树可以交换，权值相同时选取顺序也可不同），但各字母的码长及平均码长是确定的最优值。

### (3) 两种编码方案比较

哈夫曼编码的平均码长：

$$
\begin{aligned}
L_H = \sum p_i \cdot l_i
&= 0.07\times4 + 0.19\times2 + 0.02\times5 + 0.06\times4 + 0.32\times2 + 0.03\times5 + 0.21\times2 + 0.10\times4 \\
&= 0.28 + 0.38 + 0.10 + 0.24 + 0.64 + 0.15 + 0.42 + 0.40 = 2.61
\end{aligned}
$$

二进制等长编码（8 个字母用 3 位）的平均码长：$L_B = 3$。

| 维度 | 哈夫曼编码 | 二进制等长编码 |
| --- | --- | --- |
| 平均码长 | 2.61 位 | 3.00 位 |
| 存储 1 万字符所需 bit | 26100 | 30000 |
| 高频字符的码长 | 短（2 位） | 恒为 3 位 |
| 低频字符的码长 | 长（4–5 位） | 恒为 3 位 |
| 实现复杂度 | 需编码表/树 | 无需查表 |
| 解码方式 | 按哈夫曼树走 | 固定切分（每 3 位一组） |
| 唯一可译性 | 是（前缀码） | 是（定长） |

**结论：** 在字符出现频率分布不均匀的场合，哈夫曼编码通过对高频字符分配短码、低频字符分配长码，能显著降低平均码长（这里是 $3.00 \to 2.61$，约节省 13% 的空间）。代价是：编码长度不均匀，解码需借助哈夫曼树或编码表，实现稍复杂；编码表本身也要随数据一起存储，对极短消息反而不划算；变长码中一位出错可能导致后续解码错位。

## 4 堆

### (1) 建堆（最小堆）

将序列视为层序存储的完全二叉树（数组下标从 1 开始），这就是**第一步**的结果：

```text
                503(1)
             /          \
         87(2)          512(3)
        /     \         /     \
     61(4)   908(5)  170(6)  897(7)
     /   \    /
 275(8) 653(9) 462(10)
```

从最后一个非叶子结点（$\lfloor 10/2 \rfloor = 5$，即 `908`）开始，依次向前做 sift-down：

1. sift-down(5, 908)：与子 `462` 交换（`462 < 908`）。

   ```text
               503
            /       \
          87         512
         /  \       /   \
       61   462   170   897
      /  \   /
    275 653 908
   ```

2. sift-down(4, 61)：子 `275, 653`，最小 `275 > 61`，不交换。
3. sift-down(3, 512)：子 `170, 897`，最小 `170 < 512`，交换；`512` 到位置 6 后无孩子，停止。

   ```text
               503
            /       \
          87         170
         /  \       /   \
       61   462   512   897
      /  \   /
    275 653 908
   ```

4. sift-down(2, 87)：子 `61, 462`，最小 `61 < 87`，交换；`87` 到位置 4，子 `275, 653` 都更大，停止。

   ```text
               503
            /       \
          61         170
         /  \       /   \
       87   462   512   897
      /  \   /
    275 653 908
   ```

5. sift-down(1, 503)：子 `61, 170`，最小 `61 < 503`，交换。
   * `503` 到位置 2：子 `87, 462`，最小 `87 < 503`，交换。
   * `503` 到位置 4：子 `275, 653`，最小 `275 < 503`，交换。
   * `503` 到位置 8：无孩子，停止。

**最终堆：**

```text
               61
            /       \
          87         170
         /  \       /   \
       275  462   512   897
      /  \   /
    503 653 908
```

对应的层序数组：`[61, 87, 170, 275, 462, 512, 897, 503, 653, 908]`。最小元素 `61` 已经在堆顶，可以直接输出。

### (2) 最小堆的最大值元素位置

**至少有一个最大值元素位于叶子结点；若最大值唯一，它只能位于叶子结点。**

设最大值为 $M$。若某个值为 $M$ 的结点不是叶子，由最小堆性质，它的每个孩子都不小于 $M$，因而也等于 $M$。沿孩子向下，最终必能到达一个值为 $M$ 的叶子。

若允许相同关键码，最大值也可能在内部结点：例如所有结点的关键码都相同，根结点也是最大值。因此不能把"最大值只能在叶子"作为无条件结论。

> 进一步：叶子结点是编号 $\lfloor n/2 \rfloor + 1 \sim n$ 的结点，所以找最大值只需检查后一半结点。

### (3) 初始建堆的时间代价

**结论：最坏比较次数 $T(n) < 2n$，因此自底向上建堆为 $O(n)$。** 实际比较次数依赖输入序列，不能只由 $n$ 给出一个固定的等式。

**推导。** 以某结点为根的子树高度记为该结点到最深后代的边数。一次向下调整每考察一层孩子，至多比较两次关键码：先在两个孩子中选较小者，再与父结点比较；只有一个孩子时比较次数更少。最多考察与该结点高度相同的层数，因此比较次数至多为其高度的两倍。

在层序编号为 `1..n` 的完全二叉树中，结点 $i$ 的高度至少为 $j$ 当且仅当 $i \cdot 2^j \le n$，故高度至少为 $j$ 的结点数恰为 $\lfloor n/2^j \rfloor$。将每个结点的高度按层累加（高度为 $h$ 的结点在 $j = 1, \ldots, h$ 中各被计一次），可得

$$
T(n) \le 2\sum_{v} h(v) = 2\sum_{j \ge 1} \left\lfloor \frac{n}{2^j} \right\rfloor < 2\sum_{j \ge 1} \frac{n}{2^j} = 2n .
$$

这给出题目要求的线性上界；它不是每个输入的精确比较次数。

## 5 最优 $k$ 叉树（$k$ 叉哈夫曼树）

> 相关编程题：洛谷 P2168 [NOI2015] 荷马史诗（$k$ 叉哈夫曼编码，需补 0 权值虚结点）。
>
> https://www.luogu.com.cn/problem/P2168

**满 $k$ 叉树的必要条件。** 一棵每个内部结点都恰有 $k$ 个孩子的满 $k$ 叉树，若有 $n$ 个叶子结点，则内部结点数为 $\frac{n-1}{k-1}$（每次合并使树的棵数减少 $k-1$）。这要求 $(n-1)$ 能被 $(k-1)$ 整除，即

$$
n \equiv 1 \pmod{k-1}.
$$

**否则需要补"虚权值"（权值为 0 的虚拟叶结点）**，补的个数为

$$
\text{虚权值数} = (k-1) - \big((n-1) \bmod (k-1)\big) \qquad (\text{余数为 0 时不需要补}).
$$

**构造算法（与哈夫曼树类似）：**

1. 把 $n$ 个权值看作 $n$ 棵只有根结点的 $k$ 叉树（若需要，再加入相应个数的 0 权值结点）。
2. 每次从集合中取 $k$ 个**根权值最小**的树作为子树，合并成新的 $k$ 叉树，新根的权值为这 $k$ 个子树根权值之和；从集合中删除这 $k$ 棵子树，将新树加入集合。
3. 重复步骤 2，直到集合中只剩一棵树——这棵树就是最优 $k$ 叉树。

（补 0 权值等价于"第一次合并只取最小的 $k - \text{虚权值数}$ 个真实权值"。0 权值必然在第一次合并中被选中，使之后每次都能恰好取满 $k$ 个；若不补齐，最后一次合并的子树不满 $k$ 个，会浪费靠近根的位置。）

**示例：权值集合 $\{1, 2, 3, 4, 5\}$，$k = 3$。** $n = 5$，$k - 1 = 2$，$(n - 1) \bmod 2 = 0$，满足 $n \equiv 1 \pmod 2$，不需要补虚权值。

| 步骤 | 队列 | 合并 |
| --- | --- | --- |
| 初始 | 1, 2, 3, 4, 5 | — |
| 1 | 4, 5, 6 | 1 + 2 + 3 = 6 |
| 2 | 15 | 4 + 5 + 6 = 15 |

**最优 3 叉树：**

```text
        (15)
       /  |  \
      6   4   5
    / | \
   1  2  3
```

**最小加权路径长度：**

$$
WPL = 1\cdot2 + 2\cdot2 + 3\cdot2 + 4\cdot1 + 5\cdot1 = 2 + 4 + 6 + 4 + 5 = 21 .
$$

> 对比：若权值集为 $\{1, 2, 3, 4\}$（$n = 4$，$(n-1) \bmod 2 = 1$），需要补 1 个虚权值 0，第一次合并变成 $0 + 1 + 2 = 3$，之后再 $3 + 3 + 4 = 10$，得到最小 $WPL = 1\cdot2 + 2\cdot2 + 3\cdot1 + 4\cdot1 = 13$。

> **修正说明**：原答案构造算法第 2 步写"第一次合并时从原始数据中取 $(k - \text{虚权值数})$ 个"，没有指明必须取**最小的**那几个，已改为统一的"补 0 后每次取 $k$ 个最小"。其余各题答案经核对无误。
