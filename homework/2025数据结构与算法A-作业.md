> Q：按照 “C++ 的 32 位整型溢出截断” 造测试数据合理吗？虽然题面提示部分写了 “中间计算结果可能为负”。造成了python代码困难。
>
> **结论非常明确：极不合理，这甚至可以说是算法题命题中的一个典型“事故”或“偷懒导致的恶性 Bug”。**
>
> 不仅是对 Python 不公平，哪怕从纯计算机科学和 C++ 规范的角度来看，这种测试数据也是完全站不住脚的。
>
> ---
>
> **1. 从 C++ 标准来看：这是“未定义行为”（UB）**
>
> 题目依赖 32 位有符号整数溢出作为“标准答案”，在 C++ 规则中是**大忌**：
> * 在 C/C++ 语言标准中，**有符号整型溢出（Signed Integer Overflow）属于未定义行为（Undefined Behavior, 简称 UB）**。
> * 编译器在默认情况下（比如 `-O2` 或 `-O3` 开启激进优化）有权利假定“有符号数永远不会溢出”。如果在某些高版本 GCC/Clang 编译器上开启优化编译这段 C++ 代码，编译出来的机器码甚至可能会删掉某些逻辑，或者跑出和本地完全不一样的诡异结果。
> * 拿一个**违反语言规范的 UB 结果**当作标准答案，本身就是命题的失误。
>
> ---
>
> **2. 所谓“中间结果可能为负”，出题人真正想表达的并不是溢出**
>
> 出题人在提示里写“中间计算结果可能为负”，**大概率不是为了考 32 位溢出，而是为了提醒减法运算**：
> * 正常的负数来源：比如 `3 - 5 = -2`，或者 `(2 - 10) / 4 = -2`。
> * 很多初学者写的栈表达式求值，在遇到负数除法（如 `-7 / 3`）、负数出栈或栈内负数比较时容易写出 Bug。出题人本意是提醒处理普通的负数。
> * **但为什么会出现溢出？因为出题人“偷懒”了**：
>   1. 题目把长度定为 **600**。如果表达式里连续出现几个三位数连乘，数字很快就会突破几百位。
>   2. 出题人在造测试数据时，多半是写了一个**随机生成算式**的脚本。
>   3. 出题人随手用自己的 C++ 标程（里面写的是 `int`）去跑这些长算式，生成了 `.out` 答案文件。
>   4. 出题人自己的程序在跑长算式时早就**爆表了**，但他根本没去验算真实的数学结果，而是直接把这堆“算爆了的乱码”当成了评测机的标准答案！
>
> ---
>
> **3. 对 Python 等多语言极不友好，偏离了算法教学的本质**
>
> 这道题考察的核心数据结构是**“栈（Stack）”**，考察的经典算法是**“算符优先法（Dijkstra 双栈法）”**。
> * **Python 的做法在数学上是绝对正确的**：现实世界的加减乘除本来就没有“到 21 亿就倒转成负数”的道理，Python 的大整数忠实地反映了数学事实。
> * **逼着写出 `to_int32` 是一种病态的“逆向工程”**：这已经不是在考察数据结构与算法了，而是在逼着用 Python 甚至是 Java、Go 的选手去**“猜出题人当年用 C++ 写标程时踩了哪个坑”**，然后强行写一堆位运算补码黑魔法去迎合这个 Bug。
>
> ---
>
> **总结**
>
> 这种现象在国内很多老旧的 OJ（如某些高校校内 OJ、早期 POJ/OpenJudge 的老题、部分少儿编程平台等）非常普遍，被竞赛生们戏称为**“造数据用 C++，答案全凭运气合”**。
>
> 遇到这种情况不是你的代码能力或算法逻辑有问题，纯粹是踩中了命题人遗留的数据缺陷。在正规的高水平比赛（如 LeetCode 周赛、Codeforces、AtCoder、ICPC、NOI 等）中，这种将有符号整数溢出作为标程答案的题目属于重大事故，会被直接判作无效题（Rejudge / Unrated）。

### 01830 开关问题（状态搜索）
复杂度：时间 O(n·2^n)，空间 O(2^n)。

```cpp
#include <bits/stdc++.h>
using namespace std;int main(){int T;cin>>T;while(T--){int n,m;cin>>n>>m;vector<int>a(n),b(n);for(int&x:a)cin>>x;for(int&x:b)cin>>x;queue<pair<int,int>>q;int s=0,t=0;for(int i=0;i<n;i++){s=s*2+a[i];t=t*2+b[i];}unordered_map<int,int>d{{s,0}};q.push({s,0});int ans=-1;while(!q.empty()){auto [u,k]=q.front();q.pop();if(u==t){ans=k;break;}for(int i=0;i<n;i++){int v=u^(1<<(n-1-i));if(!d.count(v)){d[v]=k+1;q.push({v,k+1});}}}cout<<ans<<'\n';}}
```
```python
from collections import deque
T=int(input())
for _ in range(T):
 n,m=map(int,input().split()); a=list(map(int,input().split())); b=list(map(int,input().split()))
 s=sum(x<<(n-1-i) for i,x in enumerate(a)); t=sum(x<<(n-1-i) for i,x in enumerate(b)); q=deque([(s,0)]); seen={s}; ans=-1
 while q:
  u,k=q.popleft()
  if u==t: ans=k; break
  for i in range(n):
   v=u^(1<<i)
   if v not in seen: seen.add(v); q.append((v,k+1))
 print(ans)
```

### 03882 中缀表达式的值（双栈）
复杂度：O(n), O(n) space。

```cpp
#include <bits/stdc++.h>

```

```python
def calc(s):
 def f(a,b,o): return {'+':a+b,'-':a-b,'*':a*b,'/':int(a/b)}[o]
 v=[]; o=[]; i=0; pri={'+':1,'-':1,'*':2,'/':2}
 while i<len(s):
  if s[i].isdigit():
   j=i
   while j<len(s) and s[j].isdigit():j+=1
   v.append(int(s[i:j])); i=j; continue
  if s[i]=='(':o.append(s[i])
  elif s[i]==')':
   while o[-1]!='(':v.append(f(v.pop(-2),v.pop(),o.pop()))
   o.pop()
  else:
   while o and o[-1]!='(' and pri[o[-1]]>=pri[s[i]]:v.append(f(v.pop(-2),v.pop(),o.pop()))
   o.append(s[i])
  i+=1
 while o:v.append(f(v.pop(-2),v.pop(),o.pop()))
 return v[0]
for s in __import__('sys').stdin:
 try: print(calc(s.strip()))
 except: pass
```

### 05430 表达式·表达式树·表达式求值（表达式树）

### 03720 文本二叉树（树遍历）
复杂度：O(n), O(n) space。

每行前导 `-` 是深度；读取时维护深度到节点的栈即可恢复父子关系，再对根节点做遍历。
