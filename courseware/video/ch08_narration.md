## P2｜本章要回答三个问题

这一章围绕三个问题展开。

第一个问题：靠比较，还是靠分配？只靠两两比较来排序，最坏情况下至少要 n log n 量级次比较，这是一条下界。而桶式排序、基数排序根本不做比较，所以站在这条下界之外。

第二个问题：相等的键排完以后，还按原来的次序吗？这就是稳定性。举个例子，先按姓名排一遍，再稳定地按成绩排，那么同分的学生仍然按姓名排列。这在多关键字排序里非常有用。

第三个问题：同样是 n 的平方的量级，就一样快吗？不一样。要看最好、平均、最坏三个数，还要看额外空间。后面的实测里，冒泡比插入慢了二十七倍。

一句话概括：每读一种排序，都问四件事，比较还是分配、稳不稳定、额外空间、三种时间。答案会告诉你，同阶不等于同速。

## P6｜术语先约定清楚

先把术语约定清楚。

排序，就是把一个序列重新排成有序。本章统一对记录数组做不减排序。所谓内排序，是记录全部放在内存里；如果记录太多，排序过程中还要访问外存，那就是外排序，留到第九章讲。从这一章起，我们用记录或者元素代替前几章说的结点，用序列代替线性表。

每个记录有一个排序码域，作为排序的依据，本章假设排序码是整数。排成小的在前、允许相等的，叫不减序列；反过来叫不增序列。没有重复排序码时，分别叫升序和降序。待排序列本来就符合要求，叫正序；要整个倒过来才符合，叫逆序。

右边红框提醒一点：排序码不一定是关键码。关键码能唯一确定一个记录，而排序码不是关键码时，可能有好几个记录排序码相同，所以排序结果可能不唯一。

排序在生活里随处可见：图书按编号上架，资源管理器按名称、大小、类型排列文件，搜索引擎把最相关的网页排在前面。

## P7｜稳定：相同排序码的记录，排序后相对次序不变

这一页定义稳定性，也引出全章反复使用的一个序列。

输入是四十五、三十四、七十八、十二、三十四、三十二、二十九、六十四。里面有两个三十四，为了区分，后一个记作三十四撇，原本三十四在前。

排序之后，如果仍然是三十四在前、三十四撇在后，就是稳定的，图中绿色那一行；如果变成三十四撇跑到三十四前面，就是不稳定的，红色那一行。两行的数值完全一样，差别只在相等记录的相对次序。

稳定不是装饰。按成绩排序时，同分学生如果仍按原来的姓名顺序出现，后续的处理才有意义。后面讲 LSD 基数排序时还会看到，第一趟之后的每一趟都要求稳定，否则前几趟的成果会被打乱。

所以读每一种方法，都同时问四件事：比较还是分配，稳不稳定，额外空间多少，最好、平均、最坏各是多少。还要记住一个论证技巧：证明稳定，要对任意一对相同排序码来论证；证明不稳定，举一个反例就够了。

## P8｜怎么衡量代价：比较次数加移动次数

排序的代价怎么衡量？主要看时间；如果有特殊的空间限制，再挑辅助空间小的算法。

时间代价用记录的总比较次数和总移动次数来衡量。这里一次移动，指的是一次记录赋值。影响运行时间的因素有记录的数量、排序码和记录的大小，还有输入原本的有序程度。所以要分别考虑最佳、最差和平均三种情况。平均怎么定义？假设没有重复记录，长度为 n 的序列共有 n 的阶乘种排列，假定每种排列出现的概率相等，所有排列运行时间的平均值就是平均时间代价。

右边有一条换算要记住：一次交换等于三次移动。先把 a 存进临时变量，再把 b 赋给 a，最后把临时变量赋给 b，一共三次赋值。而插入排序把一个记录往后挪一格，只要一次赋值。

这条换算后面要用。到八点七点二节解释同样是 n 的平方的量级，冒泡为什么比插入慢几十倍，靠的就是它。

## P9｜本章的分类，以及一张先记住的总表

这张总表建议先记住，后面每讲一种方法，都可以回来对照。

直接插入和冒泡，平均都是 n 的平方的量级，都稳定；插入在小规模、近乎有序时简单有效，冒泡教学上直观，但通常不作为通用选择。选择排序也是 n 的平方，不稳定，优点是交换次数少。

堆排序是 n log n 的量级，不稳定，但最坏情况也有保证，而且原地排序。快速排序平均 n log n，不稳定，实务中最常用，但遇到坏的划分会退化。归并排序 n log n，稳定，代价是需要 n 量级的辅助空间。计数和基数排序的时间与值域或位数有关，可以做到稳定，适合整数键，它们不是比较排序。

右边是两种分类法。原书按思路分：插入类、选择类、交换类、归并，以及分配类的桶式、基数和索引排序。另一种常见分法是，插入、直接选择、冒泡叫简单排序，快排和归并叫分治排序。

本章所有实现都接受有符号整数，测试里含重复值和负数。

## P11｜直接插入：线性搜索找位置，边比边挪

直接插入排序对记录逐个处理：每来一个新记录，就和已经排好序的那部分比较，插到适当的位置。

插入要做两件事。一是找位置，从右往左比，直到遇到第一个不大于新记录的值；二是挪位置，比新记录大的都往后移一格。实现时先把当前记录暂存起来，腾出一个空位，边比边挪，挪完再把它回填到空位里。

看右边图八点一，双竖线左边是已经有序的部分。第一趟把三十四插到四十五前面；第二趟七十八不用动；第三趟十二一路挪到最前面。

注意 i 等于四那一行，插入的是三十四撇。它从右往左比，越过七十八、四十五，碰到三十四时，两者相等，就停下来，落在三十四的后面。所以相等元素不会越过彼此，三十四和三十四撇的原始顺序一直保持到排序结束。这说明直接插入是稳定的。

空间上只多一个临时变量，是常数量级。

## P12｜insertion_sort 与逐趟结果

这是 C++ 实现。外层循环从下标一开始，依次处理每个记录；先把它存到一个临时值里，空位从当前下标开始；内层循环只要空位前面那个元素比临时值大，就把它往后挪一格，空位前移；最后把临时值填进空位。

关键在红色那一行的比较：用的是严格小于。遇到相等就停，新记录就落在相等者的后面，所以稳定。如果写成小于等于，新记录就会越过相等的元素，稳定性当场消失。

右边表格是逐趟结果，和图八点一逐行一致。黄色是本趟插入的记录落点：第一趟三十四落到下标零，第二趟七十八原地不动，第三趟十二落到下标零。绿色标出 i 等于四时的关键时刻，三十四撇停在三十四后面。再往后，三十二、二十九依次插入，第七趟六十四插到七十八前面，排序完成，最终是十二、二十九、三十二、三十四、三十四撇、四十五、六十四、七十八。

## P13｜Python 版：同一策略，边界条件的代价不同

再看 Python 版。策略和 C++ 完全一样，但有一个边界条件，在两种语言里的分量截然不同。

内层循环的条件是空位大于零并且新值小于前一个元素。这个空位大于零的检查，在 Python 里是承重的，不是可有可无的防御性写法。

假如漏写了它会怎样？在 C++ 里，下标会越界，用 AddressSanitizer 检查时当场就被抓住。可在 Python 里，下标负一完全合法，它会悄悄环绕到列表的最后一个元素。程序不报任何错，却交出一个看起来正常的错答案。同一处笔误，两种结局，Python 的这种情况反而更危险。

右边说明两份实现的约定：讲算法的章节同时给 Python 实现，讲存储管理的章节只有 C++。两份代码不是逐行翻译，策略是同一份，代价却不一定相同，差在哪里，每处都会点名。

## P14｜最好线性、最坏平方；平均要靠逆置来数

插入排序的代价，分三种情况看。

最佳情况是正序，每趟只比较一次就停，比较 n 减一次；每趟暂存和回填各一次，移动二乘 n 减一次，总时间是 n 的量级。最差情况是逆序，第 i 趟要比较 i 次，移动是暂存一次、后移 i 次、回填一次，共 i 加二次。累加起来，比较 n 乘 n 减一再除以二次，移动 n 减一乘 n 加四再除以二次，是 n 的平方的量级。

平均情况要引入一个概念：逆置。排列中下标 i 小于 j、但前面的值反而更大，这样的一对就叫一个逆置。比如处理 i 等于三时，十二前面有三十四、四十五、七十八三个比它大的数，构成三个逆置，内层循环正好挪三次。所以插入排序的工作量就约等于逆置数。

平均有多少逆置呢？n 个元素两两成对，共 n 乘 n 减一除以二对。每一对要么是原序列的逆置，要么是它的完全逆转序列的逆置。等概率下各占一半，平均有 n 乘 n 减一除以四个逆置，还是 n 的平方的量级。

由此得到一条很强的结论：任何只对相邻记录做比较和移动的排序，平均时间代价都是 n 的平方的量级。这说的是一整类算法。

## P15｜Shell 排序：先跨大步，最后一趟再细排

既然一次只挪一格注定慢，能不能一步跨得远一点？这就是 Shell 排序的出发点。

直接插入的代价全花在一次只能挪一格上：一个很小的元素如果落在末尾，要一路挪回去 n 减一次。D. L. Shell 在一九五九年提出的方法，利用了插入排序的两条性质：正序时只要 n 的量级；在短序列上很有效。

做法是：把序列分成若干个不相邻、间距相同的子序列，各自做插入排序；然后缩小间距，再重复。等间距减到一时，整个序列已经基本有序，最后这趟插入排序接近 n 的量级。

所以它又叫缩小增量排序。本书按原书的取法，增量每次除以二：从 n 除以二向下取整开始，每趟整除二，直到一。

右边图八点二里，同一种连线连起来的是同一个子序列。d 等于四时，相隔四格的元素为一组；d 等于二时两两相隔；最后 d 等于一，就是普通的插入排序。

## P16｜八个数：间距四、二、一，一步跨四格

用我们的八个数走一遍。n 等于八，间距依次是四、二、一。

初始行的底色标出间距为四时的四个子序列：四十五和三十四撇一组，三十四和三十二一组，七十八和二十九一组，十二和六十四一组。各自排好后，得到三十四撇、三十二、二十九、十二、四十五、三十四、七十八、六十四。

间距为二时，偶数下标一组，奇数下标一组，各自排好，得到二十九、十二、三十四撇、三十二、四十五、三十四、七十八、六十四。最后间距为一，做一趟普通插入，得到十二、二十九、三十二、三十四撇、三十四、四十五、六十四、七十八。

但右边红框指出了代价：不稳定。三十四和三十四撇落在不同的子序列里，三十四撇在第一趟就越过了三十四，最终排在三十四前面，与输入次序相反。原因正是跨越式移动。稳定性依赖于只与相邻元素比较、绝不跳过相等元素，而 Shell 排序恰恰要跳。

## P17｜shell_sort：把插入排序里的 1 换成 gap

代码几乎就是插入排序。内两层和刚才的插入排序一样，只是把减一换成了减去间距：空位每次往前跳一个间距，比较的也是相隔一个间距的元素。最外层让间距从 n 的一半开始，每次减半，直到一。

右边表格说明，增量序列直接决定复杂度。本书用的减半增量，最坏仍然是 n 的平方的量级；Hibbard 增量，也就是一、三、七这样二的 k 次方减一的序列，最坏是 n 的二分之三次方；Sedgewick 的增量序列实测效果更好。

哪种增量序列最好，至今没有完全解决。本书取减半，并不是因为它最快，而是因为它最容易把增量这件事本身讲清楚。

## P18｜为什么除以 2 递减效果有限；换增量能换来质变

减半增量为什么还是 n 的平方的量级？问题出在增量之间不互质。间距为二的 k 减一次方的子序列，是由间距为二的 k 次方的子序列组成的，而后者上一轮已经排过了，所以后面的处理效率不高。

最坏的例子是：大数都在奇数下标，小数都在偶数下标。每一轮的子序列要么全是奇数位，要么全是偶数位，排完之后大数仍在奇数位。直到最后间距为一的那一趟，序列还远没有基本有序，最后一趟插入就得做大量的移动。

换增量能换来质变。Hibbard 增量是二的 k 次方减一，一直到七、三、一，可以证明达到 n 的二分之三次方；模拟实验甚至显示是 n 的四分之五次方，但还没有理论证明。每次除以三递减，也是 n 的二分之三次方。有的增量序列能达到 n 的六分之七次方，已经很接近 n log n 了。

下面两条边界要注意。第一，最后一趟增量必须是一。换用别的增量序列时，一定要人为补上间距一，否则不能保证有序。第二，Shell 排序不稳定，子序列互相交错、跨度又大，三十四和三十四撇就是例子。空间仍然是常数量级。

## P20｜直接选择：选出第 i 小，一次交换到位

选择排序的关键，是如何从剩余的未排序记录中找出最小的那个。这一节有两种办法：线性查找，就是直接选择；用二叉树堆，就是堆排序。

先看直接选择。第 i 轮从剩下的 n 减 i 个记录里线性扫描，找出最小者的下标，然后和下标 i 交换。代码很短：外层枚举位置，内层扫描找最小，最后一次交换。

它的比较次数是 n 减一加 n 减二，一直加到一，等于 n 乘 n 减一除以二。注意这个数与输入顺序无关，已经排好的输入照样扫这么多次，所以最好、平均、最坏都是 n 的平方的量级。

但它有一个别人没有的优点：真正改变位置的交换最多 n 减一次。代码里每轮都调用交换，最小者就是自己时，那次是白做的自交换。如果记录很大、移动很贵，而比较很便宜，直接选择反而合适。空间是常数量级。

## P21｜逐轮结果：i=3 那一轮就看得出不稳定

用我们的序列走一遍。

第零轮，最小的是十二，和下标零的四十五交换。第一轮，剩下的最小是二十九，在下标六，和下标一的三十四交换，注意三十四被一下子踢到了下标六。第二轮，三十二和下标二的七十八交换。第三轮，剩下两个三十四相等，扫描从前往后，严格小于才更新，所以先遇到的三十四撇被选中，和下标三的四十五交换。第四轮再选出三十四。然后四十五、六十四依次到位，最终是十二、二十九、三十二、三十四撇、三十四、四十五、六十四、七十八。

结果三十四撇排在了三十四前面，不稳定。到 i 等于三那一轮就已经看得出来。

更本质的原因是交换跨度很大。i 等于一那一轮，把三十四从下标一一脚踢到下标六，越过了三十四撇。稳定的排序必须避免这种远距离交换，而直接选择恰恰靠它一次交换到位。

## P22｜堆排序：用最大堆代替线性扫描来选最大

直接选择慢在每次都要线性扫描一遍才能选出最值。如果用最大堆来选，每次选最大只要对数量级的代价，这就是堆排序。

步骤是：先把数组建成最大堆；然后反复把堆顶和堆尾交换，堆的范围缩小一格，再把新的堆顶筛下去。每取一次，就把一个最大值放进后面已排好的那一段，不需要额外的数组。

上面是原书的图示。图 a 是建好的最大堆，堆顶是七十八；图 b 删除最大值七十八，用末尾的三十二替代，三十二往下筛，较大的孩子依次被提升上来；图 c 是重新建好的堆，堆顶变成四十五，七十八已经放到最后；图 d 再取走四十五，得到新的序列。

筛选时必须比较左右两个孩子，与较大的那个交换，否则堆的性质就会被破坏。

代价方面，建堆是 n 的量级，第五章已经证过；之后 n 减一次筛选，每次是 log n 的量级，合起来 n log n，而且最坏也有保证。空间是常数，但不稳定。

## P23｜sift_down 与 heap_sort：全手写，不委托标准库

这一版完全手写，不委托标准库的建堆函数。

先看筛选函数。只要当前结点还有左孩子，就先取左孩子；第五行，如果右孩子存在并且更大，就改选右孩子，也就是选左右孩子中较大的那个。如果当前结点已经不小于这个孩子，筛选结束；否则交换，继续往下。

再看堆排序本体。建堆阶段从最后一个非叶结点，也就是下标 n 除以二减一，往前逐个筛选，直到根。排序阶段，每次把堆顶换到当前堆的最后一个位置，堆缩小一格，再从根筛一次。

建堆从后往前筛，保证筛某个结点时，它的两棵子树已经是堆了。这和第五章讲的建堆方法是同一个道理。

## P24｜heap_sort 逐步：建堆 4 次筛选，排序 7 趟

## P25｜8.4 交换排序

第四节，交换排序。思路是发现逆置就交换，直到没有逆置为止。我们讲冒泡和快速排序及其两处优化，再补充几种常见写法，以及二叉搜索树排序。

## P26｜冒泡：只比较相邻两个，逆序就交换

交换排序的思想是：两两比较关键码，发现逆置就交换，直到没有逆置对为止。

冒泡排序是最朴素的一种。它不停地比较相邻的两个记录，逆序就交换。一趟走完，最大或最小的那个必然被顶到一端，就像气泡从水底冒上来，所以叫冒泡。

右边图八点五是原书的写法：从数组末端往前比，每趟把最小的推到最左边。比如第一趟，十二被一路推到下标零；第二趟，二十九被推到下标一。本书反过来，从前往后比，每趟把最大的顶到最右边。原书自己也说，这取决于编程人员的个人喜好，两种写法对称等价。

还有一个关键优化，原书算法八点五就有：记一个本趟有没有交换的标志。如果一整趟下来一次交换都没有，说明序列已经有序，立刻结束，不必再跑剩下的趟数。

---

## P27｜bubble_sort：本趟无交换即结束

代码里，外层让右端界从 n 逐趟减一；每趟开始时把标志设为假；内层从左往右比较相邻两个，后一个严格小于前一个才交换，并把标志设为真；一趟结束如果标志仍为假，直接返回。

右边是逐趟结果，绿色是本趟被顶到位的最大者。第一趟七十八到最右，第二趟六十四，第三趟四十五，第四趟三十四撇，第五趟三十四。到第五趟时序列已经有序，但这一趟里还发生过交换，所以还要再跑第六趟；第六趟一次交换都没有，于是结束。

为什么稳定？因为只有严格小于才交换，相等的两个元素永远不会互换。第三趟，三十四往右走碰到三十四撇就停下，改由三十四撇接着往右走；第四趟，三十四往右走，又停在三十四撇左边，始终是三十四在前。把小于写成小于等于，稳定性当场消失，这是最容易犯的错。

代价方面，最好是有序输入，第一趟就退出，n 的量级；最坏是逆序，比较 n 乘 n 减一除以二次，n 的平方的量级。

## P28｜快速排序：分、治，不用合

快速排序是 Tony Hoare 在一九六二年提出的，被评为二十世纪十大算法之一，平均是 n log n 的量级。

它分四步。第一，从序列中任选一个记录作为轴值；第二，把其余记录分割成左子序列和右子序列；第三，左边的都小于等于轴值，右边的都大于等于轴值，于是轴值正好落在它的最终位置上；第四，对左右两部分递归，直到子序列只含零个或一个元素。

轴值一旦到位，左边的记录再也不会跑到它右边。所以快排不需要明显的合并步骤，这是它和归并排序最大的区别。

右边图八点六：第一层以三十二为轴值，分成二十五、二十九、十二和三十四撇、六十四、四十五、三十四两部分；左边再以二十九为轴，右边以六十四为轴，一层层分下去。

不妨把它看成一棵二叉树：轴值是子树的根，左右子序列是左右子树。对这棵树做中序遍历，收集轴值和叶子，就是排序结果。

---

## P29｜轴值怎么选，影响很大

轴值怎么选，对快排的影响非常大。

如果选第一个或最后一个记录，一旦输入恰好是正序、逆序或者全部相等，每次分割都会把剩余记录全分到一边，另一边是空的。分治法根本起不到作用，递归深度是 n，时间是 n 的平方的量级。

如果选中间点，也就是起点加终点除以二，那么正序或逆序输入时正好平分序列，实验效果非常好。实务中的快排一定要配三数取中或随机枢轴。

本书的实现选区间的末元素作为枢轴，把更小的元素换到左侧，再递归两边。它有一条硬要求：全相等的输入也必须能结束。它确实能结束，只是退化成 n 的平方。

还有一个细节：等于轴值的记录怎么办？快排本来就不稳定，处理方法有多种。原书算法八点六的注释里说，小于等于也可以改写为小于，只是会增加记录移动。两种都对，差别在移动次数；重复值多的时候，还关系到分得均不均匀。

## P30｜图 8.7：两端交替找空闲位置，把逆置记录移过去

这是原书的分割方法，待分割序列是二十五、三十四、四十五、三十二、三十四撇、十二、二十九、六十四，选中间的三十二作轴值。

第一步准备：轴值三十二和末记录交换，并存入临时变量，末位成了空闲位置，图里用方框表示。第二步，l 向右，越过小于等于轴值的二十五，停在三十四，因为它大于三十二，把它放到右端的空闲位，l 处空出。第三步，r 向左，找小于轴值的，停在二十九，把它放到 l 处的空闲位，r 处又空出。

如此交替：l 再找到四十五，填到右边；r 找到十二，填到左边；l 找到六十四，填到右边。最后 l 和 r 相遇，整个序列扫描完毕。此时的空闲位置正是轴值的正确位置，回填三十二，得到二十五、二十九、十二、三十二、三十四撇、六十四、四十五、三十四，左边都小，右边都大。

分割是快排的全部工作量，是一次 n 量级的线性扫描。分得均不均匀，决定了递归有多深：每次平分是 n log n，每次只切下一个元素就是 n 的平方。另一种写法是 l、r 各停在逆置记录上，直接交换。

## P31｜本书的 partition：末元素当轴，一趟扫描

本书的分割换了一种写法：末元素当轴，从左到右只扫一趟。

代码里，轴值取区间最后一个元素，设一个边界，从区间起点开始。扫描每个元素，如果它严格小于轴值，就和边界处的元素交换，边界后移一格。扫描结束后，再把轴值换到边界处，返回边界。

理解它要靠下面的循环不变式，区间都是左闭右开。从起点到边界之前，都小于轴值；从边界到当前扫描位置之前，都大于等于轴值；最后一个位置是轴值本身。每处理一个元素，这个不变式都保持成立。

所以扫描结束、把轴值换到边界之后，左边都更小，右边都不小于它。等于轴值的元素都留在右侧。全相等时，每次只切下一个元素，但一定能结束，只是代价是 n 的平方的量级。

## P32｜partition 手算：demo 数据，轴为 1

现在揭开开头留下的那件事。用开头的数据：三、负二、七、三撇、零、负二撇、九、一，两个重复值分别加撇区分。轴值是末元素一。

逐个扫描：三不小于一，跳过；负二小于一，和下标零交换，边界变成一；七和三撇都跳过；零小于一，和下标一的三交换，边界变成二；负二撇小于一，和下标二的七交换，边界变成三；九跳过。最后把下标三和下标七交换，轴值一归位，数组是负二、零、负二撇、一、三、七、九、三撇，返回三。

接着递归左右两段，最终得到：负二撇、负二、零、一、三撇、三、七、九。

相等键被打乱了。左段以负二撇为轴，没有更小的元素，负二撇被换到下标零，越过了负二。右段以三撇为轴，同样把三撇换到了三前面。

这就是开头那句快排不保证的含义。输出看起来一样，只是因为整数看不出谁是谁。

## P33｜双指针分割：首元素当轴，两头各找一个逆置就交换

再补充一种笔试和 OJ 里最常见的分割：双指针。例子是五、三、八、六、二、七、一、四，首元素五当轴。left 从下标一向右找大于五的，right 从下标七向左找小于五的。

第一次，left 停在下标二的八，right 停在下标七的四，交换八和四。第二次，left 停在下标三的六，right 停在下标六的一，交换六和一。第三次，left 走到下标五，right 退到下标四，两个指针交错，扫描结束。最后把首位的轴值和 right 处的二交换，五归位到下标四，得到二、三、四、一、五、七、六、八。

为什么和 right 交换？因为交错时，right 停在最后一个小于等于轴值的位置，把它换到首位，不会破坏左边都不大于轴值的性质。

和前面两种比较：原书是挖空位、交替填坑；本书的 C++ 用 Lomuto 写法，末元素当轴，单向扫一趟；这里是两头相向、成对交换，交换次数大约只有 Lomuto 的三分之一。

## P34｜quick_sort 加 partition：双指针版

这是双指针版的 Python 代码。主函数很简单：区间至少两个元素时，先分割，再对轴值两侧递归。

分割函数里，轴值取首元素，left 从轴的下一位开始，right 从末尾开始。外层是一个无限循环：left 向右跳过小于等于轴值的元素，right 向左跳过大于等于轴值的元素；如果两个指针交错，就跳出；否则交换这两处。最后把轴值和 right 处交换，返回 right。

右上角提醒：两个内层循环都要带上 left 小于等于 right 这个条件。少了它，left 会越过区间右端，right 会退到轴的左边。

红框是这个版本的弱点：全相等的输入会退化。两边都跳过等于轴值的元素，比如两千个七，left 一路走到底，每次只切掉一个，递归一千九百九十九层，大约两百万次比较。Hoare 的原版让两边遇到相等也停下来交换，就能对半分。

另外它仍然不稳定，成对交换是跨越式移动；首元素当轴，有序输入照样是 n 的平方的量级。

## P35｜列表推导版：三行写完，但不是原地排序

Python 里还有一个很流行的写法：列表推导版快排。首元素当轴，用两个列表推导，把小于轴的收进左边，大于等于轴的收进右边，然后递归排好左右，再和轴值拼起来。例子输出一、二、四、四、五、六、八、十六、十八。

下面的表格把它和双指针版对比。双指针版是原地的；列表推导版不是，每一层都新建列表。双指针版不稳定；列表推导版却是稳定的，因为推导保持原来的次序，等于轴的元素都放在轴后面。额外空间上，双指针版只占栈，平均 log n 的量级；列表推导版平均是 n 的量级，退化时 n 的平方。有序输入时两者都是 n 的平方，列表推导版一千个元素就会抛出递归错误。

右上角的提醒很重要：稳定性看写法，不看名字。旧版讲义曾把这一版标成不稳定，其实它恰好稳定；不稳定的是原地分割。说快排不稳定，指的是原地版本。

怎么改才不退化？用随机轴，再分成小于、等于、大于三个列表。这样有序输入、全相等输入都不会再一次只切一个。

## P36｜quick_sort_range 与三种情况的代价

本书的快排主体很短：区间少于两个元素就返回；否则分割，得到轴的位置，然后分别对左右两段递归。对外的接口就是对整个数组调用一次。

代价分三种情况。

最差情况，每次只切下一个元素，要做 n 量级次分割，时间是 n 的平方的量级；每层递归在栈上存一个轴值，栈的深度是 n，空间也是 n 的量级。

最好情况，每次恰好平分。递推式是 T 的 n 等于两倍 T 的 n 除以二，再加 c 乘 n。两边同除以 n，逐层叠加，共 log n 层，结果是 n log n 的量级。

平均情况，假设轴值落在各个位置的概率都是 n 分之一。T 的 n 等于 c 乘 n，加上 n 分之二乘以所有较小规模 T 的和。把相邻两个规模的式子相减，再同除以 n 乘 n 加一，逐项叠加，得到的仍是 n log n 的量级，空间是 log n 的量级。

所以快排平均很好，最坏很差，关键就看分割均不均匀。

## P37｜同一个缺陷：Python 里真的崩，C++ 里只是慢

同样的快排，翻译成 Python，会遇到一个在 C++ 里不明显的问题。

这一版末元素当轴，遇到已经排好序的输入，就退化成 n 层递归。在 C++ 里，默认有八兆字节的栈，几万层才会栈溢出，所以表现只是慢。可在 CPython 里，递归上限默认是一千层，一千个有序元素就会抛出递归错误，程序直接崩溃。

同一个算法缺陷，在两种语言里暴露出来的阈值，差了两个数量级。

这就引出下一页要讲的优化：只对较短的一侧递归。在 C++ 里，它的作用是省栈；在 Python 里，它决定的是程序能不能跑完。本书的测试里也有断言，把这两件事都钉住了。

## P38｜两处对策：短侧递归加小区间插入

针对快排的两个问题，这里有两处对策。

第一处，递归太深，就只递归短侧。每次分割后，比较左右两段的长度，较短的一侧递归处理，较长的一侧不递归，而是修改区间边界，回到循环开头继续处理。因为每次递归的区间至少比原来减半，递归深度就被压到了 log n 的量级。这是本书补充的。

第二处，小区间改用插入排序，这是原书算法八点七的做法。只剩十几个元素时，递归调用和划分的固定开销已经超过了收益，不如直接插入。代码里，循环条件是区间长度大于十六，循环退出后，对剩下的小区间当场做一次插入排序。

本书阈值取十六，每个小区间当场插入排序；原书取二十八，最后对整个序列做一次插入，总代价同阶。阈值多少最合适，要在自己的机器上重新测。

## P39｜两处优化管的是栈深与常数，管不了最坏时间

不过要清醒：这两处优化管的是栈深和常数，管不了最坏时间。

看八点七点二节的实测，两万个已经排好序的数。优化后的快排用了一百零五点九毫秒，直接插入几乎是零毫秒。

原因是，优化快排的枢轴仍然取末元素，有序输入下每次划分都是最坏情况，比较次数是 n 的平方的量级。而插入排序面对有序输入，内层循环一次都不进，只要 n 的量级。

想根治，得换枢轴策略，比如三数取中或随机枢轴，那是习题里的事。顺便说一句，原书的实现取中间点作轴值，所以原书的实验里，快排处理正序和逆序一样快。同一个算法，选轴策略不同，对输入形态的反应可以完全相反。

## P40｜二叉搜索树排序：插入就是分割，中序就是收集

最后补充快排的另一面：二叉搜索树排序。

代码很简单：把每个数依次插入一棵二叉搜索树，小于结点值的往左走，否则往右走。注意相等时进右子树，这样能保持先后次序。全部插完后，做一次中序遍历，收集出来的就是有序序列。

右边是五、三、八、六、二、七、一、四建出的树。根是五，三和八是它的左右孩子；三下面是二和四，二下面是一；八下面是六，六的右孩子是七。

它和快排做的是同一批比较。根五就相当于首元素当轴：后面每个数插入时，都先和五比，分到左子树或右子树，这正是一次分割。子树再按各自的首元素分下去。比较的对象、比较的次数，与首元素当轴的快排完全相同。

所以它的代价也和快排一样：平均 n log n；有序输入时树退化成链，是 n 的平方，递归也很深。要保证最坏情况，就得换成 AVL 树或红黑树，这是第十二章的内容。

## P42｜归并排序：分得随意，合得用心

归并排序分三步：把序列划分成两个子序列；分别递归地归并排序；再把两个有序子序列合并成一个。

合并的方法是：每次比较两个子序列的头，取较小的那个放进结果，它后面的记录顶上来，继续比较。区间长度小于二时已经有序，递归停止。每一层合并总共扫描 n 个元素，一共 log n 层，所以 T 的 n 等于两倍 T 的 n 除以二加 n 的量级，结果是 n log n 的量级。

右边图八点八：八个数先一层层对半划分，直到每段一个元素；再两两归并，变成长度二的有序段、长度四的有序段，最后归并成十二、二十五、三十二、三十四、三十四撇、四十五、六十四、七十八。

下面的表格把它和快排对照。快排的分要用轴值分割，这是它全部的工作量，合却不需要；归并的分只是对半切，常数时间，合才是线性归并，是全部工作量。最坏情况下，快排是 n 的平方，归并始终是 n log n，不依赖输入。

空间上，只分配一个与输入等长的缓冲区，所有递归层复用，辅助空间是 n 的量级，栈另占 log n。

## P43｜merge_ranges / merge_sort_range / merge_sort

代码分三个函数。

第一个是合并两个相邻有序段。左指针从左段开头开始，右指针从右段开头开始，输出指针从区间起点开始。两段都没取完时，每次比较两个段头，取较小的写入缓冲区。一段取完后，另一段剩余的部分照抄。最后把缓冲区里这一段拷回原数组。

关键在第七行：只有右侧严格更小，才取右侧；相等时先取左侧。左段的记录原本就在右段前面，所以相等的记录保持原来次序，这就是稳定性的来源。原书的注释也写着：为保证稳定性，相等时左边优先。

第二个函数是递归主体：区间少于两个元素就返回；否则取中点，分别排好左右两半，再合并。

第三个函数是入口。缓冲区在这里一次开够，长度和输入一样，传给所有递归层复用，而不是在递归里反复申请内存。

## P44｜最后一次合并：两段各四个元素

手算最后一次合并。两段取自图八点八倒数第二行：左段是二十五、三十二、三十四、四十五，右段是十二、三十四撇、六十四、七十八。

第一步，十二小于二十五，取右，输出十二。第二步，三十四撇不小于二十五，取左，输出二十五。第三步，左段头三十二仍然小于三十四撇，取左。

关键是第四步：左段头三十四，右段头三十四撇，两者相等。判断条件是右侧是否严格小于左侧，答案是否，所以取左，先输出三十四。第五步，三十四撇小于四十五，取右，三十四撇紧跟在三十四后面。第六步取四十五，左段取完。第七步右段剩下的六十四、七十八照抄。最终是十二、二十五、三十二、三十四、三十四撇、四十五、六十四、七十八，三十四仍在前面。

所以稳定性的全部来源就是这个小于号：相等取左。写成小于等于就会取右，稳定性当场消失。

不过 C++ 版验证不了这一点，整数数组里两个相等的数换不换位置，排完一模一样。Python 版能排任何可比较的对象，测试就用只按键比较、附带数据不参与比较的记录，检查附带数据是否仍是入场顺序。把小于改成小于等于，断言马上就会失败。

## P45｜归并排序的两处优化

接着看归并排序的优化版本。原书算法八点九提了两处优化，本书保留了其中一处，另一处换成了更实用的做法。

第一处，小区间改用直接插入排序。代码开头判断，区间长度小于等于十六时，不再继续二分递归，而是就地做一遍直接插入。道理很简单：递归到只剩十几个元素时，计算中点、调用函数这些固定开销，已经超过了归并本身带来的好处，而插入排序在小规模数据上常数很小。

第二处在合并之前。左右两半各自排好以后，先看一眼左半段的最后一个元素和右半段的第一个元素：如果左边最后一个小于等于右边第一个，说明两段本来就接得上，整个区间已经有序，这一趟归并直接跳过。代码里只有右段开头严格小于左段末尾时，才调用合并。这个判断对有序输入特别有效，搬移量从 n log n 的量级压到接近线性；随机输入几乎不会命中，但判断本身只花一次比较，不亏。

## P46｜归并还能怎么改进；什么时候选它

除了刚才两处，归并排序还有两种经典改进。

一种是 Sedgewick 的监视哨技巧。把数据复制到临时数组时，故意把第二个子数组颠倒过来放。这样两个子数组从两端向中间推进，彼此充当对方的监视哨，循环里就不用反复检查某一段是不是已经取完了。

另一种是小区间当场做插入排序，原书取的阈值是二十八。要注意，原书正文说像优化快排那样，最后对整个序列做一次插入排序，这对归并是行不通的：归并要求两半必须各自有序才能合并，所以小段只能当场排好。原书算法八点九的代码本身也是逐段做的。

再看下面的结论表。时间上，最大、最小、平均都是 n log n 的量级，对初始排列不敏感，速度很稳定；空间上要 n 的量级的辅助数组，这是简单排序和堆排序都没有的代价；它是稳定的，C++ 标准库的 stable sort 用的就是归并排序。

## P47｜逆序对计数：在合并里多写一句

归并排序还有一个很有用的副产品：数逆序对。

回忆八点二点一节的逆置：下标 i 小于 j，而前面的元素反而比后面的大，就是一对逆置。直接插入排序挪位的总次数恰好等于逆置数，所以照着插入排序去数，要 n 的平方的量级；用归并排序，n log n 就能数完。

思路是分治。任何一对逆置，要么两个元素都在左半段，要么都在右半段，这两种交给递归去数；剩下一左一右的，在合并时数。合并时两段各自有序，当右段当前元素严格小于左段当前元素时，左段里还没输出的那些元素全都比它大，于是一次记上 middle 减 left 个。相等时取左边、不计数，因为相等元素不构成逆置，这和稳定性来自同一个小于号。

看右边的手算：序列二、四、一、三、五，左段二、四，右段一、三、五。一小于二，取右，左段还剩两个，加二；然后取二；三小于四，取右，加一；再取四，最后照抄五。两个子段内部各零个，合计三对：二和一、四和一、四和三。

## P48｜带计数的合并

唯一多出来的是红色标出的那一句，在第十三行：当右段当前元素严格小于左段当前元素时，计数器加上 middle 减 left，也就是左段剩下的元素个数。注意这里用的是左闭右开区间。如果你习惯写闭区间，左段从 i 到 mid，同样的量就写成 mid 减 i 加一，这就是很多题解里常见的那个公式，两者是一回事。

## P49｜计数不顺手排序；结果必须 64 位

递归框架很直接：区间长度小于二就返回零；否则取中点，左半段的逆序对数，加右半段的，再加上合并时数出来的，三项相加。

这里有两个工程上的细节。第一，计数不应该顺手把调用方的数组排了序。数逆序对是一个查询，调用方不一定希望原序列被改动。所以 C++ 版对外的函数按值传参，在副本上归并；如果调用方本来就要排序，可以用 move 把数组交进来，省掉这次拷贝。Python 版同理，先复制一份列表再归并。

第二，结果必须用六十四位整数。n 个元素最多有 n 乘 n 减一除以二个逆序对，n 达到六万五千五百三十七时就超过了 int 的上限。比如七万个元素的递减序列，答案应该是二十四亿四千九百九十六万五千。累加器如果写成 int，未定义行为检测工具会报有符号溢出，开了 O2 优化则会悄悄给出错误的数。在 OJ 上，这就是常说的答案要开 long long。

## P50｜变形题与另一条路

数逆序对的思路可以推广。左边是一道变形题，留作练习：求满足 i 小于 j，并且 a 的第 i 项加 a 的第 j 项，大于 b 的第 i 项加 b 的第 j 项的对数。

先移项，令 c 等于 a 减 b，条件就变成 c 的第 i 项大于 c 的第 j 项的相反数。这仍然是前面的数比后面某个量大的形式，所以可以在归并时拿左段去和右段比，先用双指针数完，再照常合并。更进一步，条件等价于两项之和大于零，对 i 和 j 是对称的，i 小于 j 这个限制其实不起作用，把 c 排序后直接双指针也能数，正好用来对拍。

右边是数逆序对的另一条路：离散化加树状数组。从左往右扫描，把每个值换成它在全体值中的名次；树状数组记录已扫过的值里各名次出现几次。扫到某个元素时，前面比它大的个数，等于已扫过的个数减去名次不超过它的个数。查询和更新都是 log n 的量级，相等元素同样不计入。归并法不需要离散化；树状数组法的优势是序列动态追加时还能继续回答。

## P51｜OJ 02299 Ultra-QuickSort

来看一道上机题，OJ 零二二九九，Ultra-QuickSort。题目问：只能交换相邻的两个数，把序列排好最少要交换几次？

这其实就是数逆序对。八点二节讲过，每次相邻交换恰好消掉一个逆序对，所以最少交换次数就等于逆序对数。n 最大五十万，n 的平方的冒泡模拟肯定超时，要用 n log n 的归并来数。样例里，九、一、零、五、四有六个逆序对，一、二、三是零个。

代码的关键在合并的判断：左段当前元素小于等于右段当前元素时取左边；否则取右边，并且加上左段剩下的个数。这里必须写小于等于。排序讲义旧版的模板写的是严格小于，相等时会先取右边，把相等的一对也算成了逆序。比如二、二、一，正确答案是二，用严格小于会数出三。

## P52｜分配排序和索引排序

下面进入八点六节，分配排序和索引排序。这类方法不再比较关键码，代价是要事先知道记录的一些情况。我们依次讲桶式排序、区间桶排序、基数排序和索引排序。

## P53｜跳出比较模型

为什么要跳出比较？八点七点三节会证明，基于比较的排序最坏至少要 n log n 量级的比较次数。想突破这个下界，唯一的办法就是不再比较，转而利用关键码本身的数字结构，直接算出每个元素该去哪儿。这就是分配排序：它的唯一特征是不需要关键码之间的比较，但需要事先知道记录序列的一些具体情况。

下面三张卡片对应三种情况。排序码都落在某个小区间，零到 m 之内，就用桶式排序，开 m 个计数器，数一遍再累加。值域 m 很大，就用基数排序，把排序码拆成 d 位，每一位做一次桶式排序。记录本身很大、搬不起，就用索引排序，只移动指针或下标，不动记录本身。

---

## P54｜桶式排序：先数一遍，把计数累加成位置

看原书的例子：m 等于十，序列是七、三、八、九、六、一、八撇、一撇、二。

第一步，数一遍每个取值出现几次：一出现两次，二、三各一次，六、七各一次，八两次，九一次，其余是零。第二步，把计数从左往右累加，得到零、二、三、四、四、四、五、六、八、九。累加以后，计数数组的第 i 个元素表示小于等于 i 的元素共有几个，也就是取值 i 在结果中的结束位置。

第三步，按累加结果把元素放回去，关键是要从原序列尾部往前扫。看高亮的八：累加值是八，说明值为八的元素占结果的下标六和七。倒着扫，先遇到八撇，放到下标七，计数减一；后遇到八，放到下标六。两个八的先后次序没变，这就是稳定性的唯一来源。如果正着扫，八会先占下标七，次序就反了。

另外，先数再累加的做法，只需要一个长度为 n 的辅助数组，不用 m 条变长的链。

---

## P55｜计数排序：与原书不同的三处

本书的计数排序实现和原书有三处不同。

第一，不要求下界为零。先扫一遍找出实际的最小值和最大值，按元素值减最小值来计数，这样负数也能直接排，不用调用者先平移。C++ 里计算值域长度时必须先转成 long long，因为最大值减最小值再加一，在 int 里自己就可能溢出。

第二，值域太稀疏时直接抛异常。计数排序的时间和空间都是 m 加 n 的量级，m 是值域长度。如果只排十个数，值域却是零到十亿，就要分配十亿个计数器。所以值域超过一千万时直接抛出参数错误，当场失败，好过把机器拖垮。

第三，本书是按计数重建取值，而不是搬移原记录。对纯整数，输出完全一样；但如果记录带着卫星数据，比如学号、姓名，就必须回到原书的写法：倒序扫描，搬移原记录。

---

## P56｜桶式排序只在 m 较小时才有实际意义

计数排序的时间是 m 加 n 的量级：扫一遍计数，累加 m 个计数器，再输出 n 次。空间是 m 个计数器加一个长度为 n 的临时数组。

所以能不能用，要看 m 和 n 的比值。左边表格列了三种情况：m 和 n 同阶时，时间是线性的，相对比较排序是一次飞跃；m 是 n log n 量级时，时间也是 n log n，没有优势，还倒贴额外空间；m 是 n 的平方量级时，就不如比较排序了。这正是下一节要把大值域拆成若干小值域的原因。

右上角说的是 Python 版的差别。Python 整数没有宽度，溢出的坑不存在；但减去最小值这一步不能省。负数下标在 Python 里是合法的，负一号会环绕到列表末尾，不报错，却给出错答案，比如三、负一、二会排成二、三、三。值域上限检查也不能少，它挡的是内存。

最后一点：分配排序天然稳定。同一个桶里的记录按进桶顺序出桶，整个过程没有任何一次比较能打乱它们，前提是收集方式保持入桶顺序。

## P57｜另一种桶排序：按区间分桶，桶内再排

还有一种也叫桶排序的方法，按区间分桶，和刚才的计数排序不是一回事。

假设数据都在零到一之间，并且近似均匀分布。开 k 个桶，第 i 个桶装从 k 分之 i 到 k 分之 i 加一这一段区间，元素乘以 k 取整就是桶号。分完以后，每个桶内部用直接插入排序，它是稳定的；最后按桶号依次收集。样例输入十个小数，输出就是从零点一二、零点一七一直到零点九四的有序序列。

右边表格做了对比：计数排序一个桶装一个值，桶内不用排，适合值域小的整数，时间是 n 加 m；区间桶排序一个桶装一段区间，桶内要再排一次，适合分布均匀的实数，平均时间是 n 加 k。

要警惕的是它依赖分布。均匀时每个桶期望只有常数个元素，总代价是线性的；如果全挤进一个桶，就退化成对那个桶做插入排序，变成 n 的平方。数据不在零到一之间时，先减最小值、再除以最大值与最小值之差来映射桶号，全部相等时要特判，否则会除以零。另外，原书说的桶式排序，其实就是计数排序。

## P58｜基数排序：MSD 与 LSD

值域 m 很大时，计数排序开不出那么多计数器，办法是把排序码按进制拆开。比如零到九九九九，可以拆成千位、百位、十位、个位，每一位只有十种取值。子码也可以是不同类型，比如扑克牌按花色和面值两个子码排序。基数 r 就是每一位的取值个数：十进制是十，二进制串可以取二、四、八、十六，字符串取二十六。

拆开以后有两种顺序。MSD 是高位优先：先按最高位分成若干子序列，再对每个子序列按次高位分，一直分下去，最后收集，是递归分治。LSD 是低位优先：从最低位开始，每一趟对全体做一次分配、收集，再进入高一位。

左下角的扑克例子：MSD 先按花色分成四组，再在组内按面值排；LSD 先按面值排一趟，再按花色稳定地排一趟。两种走法最终得到同一个序列。

为什么计算机常用 LSD？MSD 要递归处理各个子集，虽然可以逐层复用桶；LSD 逐位对全体统一分配、收集，结构规整，但要求每一趟都必须稳定。本节都讨论 LSD。

## P59｜LSD 走一遍

用一个具体例子走一遍 LSD：九个两位数，九十七、五十三、八十八、五十九、二十六、四十一、八十八撇、三十一、二十二，d 等于二，r 等于十。

第一趟按个位分配。个位是一的有四十一、三十一，是二的有二十二，然后是五十三、二十六、九十七，个位是八的有八十八和八十八撇，最后是五十九。收集起来得到：四十一、三十一、二十二、五十三、二十六、九十七、八十八、八十八撇、五十九。左边的图就是这一趟的计数、累加和收集，和桶式排序完全一样。

第二趟按十位。十位是二的有二十二和二十六，它们在第一趟里已经按个位排好，这一趟稳定地保留了这个次序。最终得到二十二、二十六、三十一、四十一、五十三、五十九、八十八、八十八撇、九十七。

注意高亮的八十八和八十八撇，两趟下来始终保持原来的先后。这就是每一趟都必须稳定的原因：否则高位那一趟会把低位排好的次序打乱。

## P60｜按字节 4 趟，翻转符号位

C++ 版的基数排序按字节拆分：三十二位整数，每趟取八位，一共四趟，每趟二百五十六个桶。

有一个关键技巧：把每个值转成无符号数之后，和最高位为一的那个常数做异或，也就是翻转符号位。为什么？补码表示下，负数的最高位是一，如果直接按无符号序排，负数会排到最大。翻转符号位以后，负数的位模式整体落到正数前面，顺序就对了。

每一趟的结构就是桶式排序：先计数，再把计数转成位置，然后分配到辅助数组，最后交换两个数组。第十一行把计数转成的是起始位置，而不是结束位置，所以从前往后扫也是稳定的，和前面倒着扫是同一招的两种写法。

代价是 d 乘以 n 加 r 的量级，这里 d 等于四，r 等于二百五十六。把值域 m 换成了位数 d 和基数 r，零到二的三十二次方这么大的范围也排得动。

## P61｜Python 版：没有最高位

Python 版的基数排序，是本章最值得看的一处语言差异。

C++ 的 int 是定长补码，翻转符号位就能处理负数。可 Python 的整数是任意精度的，根本没有最高位这个概念：负一的二进制，在概念上是无限长的一串一。所以 C++ 的技巧在 Python 里不成立。

Python 版换了一种办法：整体平移。看红色的几行，先求出最小值，把所有元素减去它，平移到非负区间；然后每趟取八位做计数排序，直到最大的键右移后变成零为止；排完再把最小值加回来。代价是多一次求最小值的扫描，换来的是完全不依赖任何机器字长。哪怕元素大到十的三十次方，这个方法照样成立，测试就是拿这个规模来钉住它的。

## P62｜显式的桶：固定容量队列

刚才的写法用计数数组充当隐式的桶。原书还有一种更直观的写法，用队列作为显式的桶，代码八点十二就是这个队列。

它是一个固定容量的循环队列：容量在构造时定下，不会扩容。入队时满了就返回失败，出队时空了就返回空值；队尾位置由队头加元素个数，再对容量取模得到，这就是环绕。右边的图是第一趟按个位分配之后的十个队列：四十一和三十一进了一号队列，八十八和八十八撇进了八号队列，和刚才手算的结果一致。

要强调的是，它不是标准库队列的替身，而是专门给基数排序当桶用的。Python 一侧没有实现它，因为容量、环绕这些属于存储管理的问题。

## P64｜基数排序到底是不是线性的？

现在问一个问题：基数排序到底是不是线性时间的？

看起来是。时间是 d 乘以 n 加 r 的量级，r 远小于 n 时，比如十或二十六，都是常数，可以忽略，得到 d 乘 n；如果 d 相对 n 很小，那就是线性的。这样看，它似乎是最快的排序算法。

但其实不是。n 个互不相同的关键码需要 n 个不同的编码，所以位数 d 至少是以 r 为底 n 的对数，d 不能再当常数。时间就变成 n 乘以以 r 为底 n 的对数；r 等于二时就是 n log n，和堆排序、快排、归并同一个量级。

这里还藏着一个默认假设：常数时间比较。三十二位整数的位数几乎都比 log n 大，比较两个长整数理论上也要 log n 的量级，但人们认为整数比较是常数时间。正是这条假设，让上面那笔账能算出差别。

最后是一处值得抄下来的工程优化：基数取二的 g 次方时，取第 i 位不用循环做 i 次除法，改用移位和按位与。原书实测一百万个数据、r 等于十六时，时间从零点六五七零秒降到零点五五三二秒。

## P65｜索引排序：记录一个都不动，动的是索引

前面所有算法都在搬记录。可如果记录很大，比如一条学籍几百字节，一张图片几兆，搬移的代价就会压过比较的代价。

办法是：数组里存指向记录的指针或下标，排序时只动指针，记录一个都不动。八点六点二节的静态链基数排序，其实也是一种索引排序。这是用空间换时间；排完以后如果要按索引整理原数组，这一步必须做到线性时间，否则省下的搬移又还回去了。

我们采用原书表八点一的第二种约定：索引数组的第 i 个元素，表示结果的第 i 位应该从原数组的哪个下标取值。看下面的表，排序码是二十九、二十五、三十四、六十四、三十四撇、十二、三十二、四十五。最小的十二在下标五，所以索引第零位是五；接下来二十五在下标一，二十九在下标零，依此类推，得到五、一、零、六、二、四、七、三。按索引取值，就是有序序列。注意高亮的三十四和三十四撇，索引里二排在四前面，次序保持不变。

## P66｜排的是索引，不是记录

排索引可以用任何排序方法，原书算法八点十四用的是直接插入。

代码一开始，把索引数组初始化为零、一、二，一直到 n 减一。然后就是标准的直接插入排序，只不过比较时比的是索引所指的原数组元素，移动时挪的是索引。原数组按常量引用传入，从头到尾一次都不写，动的只有索引数组。

稳定性是免费得来的。插入排序遇到相等元素就停，不会越过它，所以三十四和三十四撇的先后不变，索引里二排在四的前面。

代价与收益也很清楚：多用一个长度为 n 的索引数组，换来排序阶段一次记录搬移都没有。

## P67｜沿置换环整理

有了索引，如果最后要把原数组真正排好，怎样才能做到线性时间？答案是顺着置换环走。

从下标零开始：零号位置该放五号的值，五号位置该放四号的值，四号该放二号的值，二号该放零号的值，一圈回到起点。沿着这个环，先把零号的值存进临时变量，然后依次把值往前挪，最后把临时变量放进二号位置，这一环上的元素一次全部到位。每到位一个，就把它的索引改成自己的下标，不再参与后面的环。

看下面的表。处理完环零、五、四、二以后，数组变成十二、二十五、二十九、六十四、三十四、三十四撇、三十二、四十五。下标一的二十五本来就在位，不动。再处理环三、六、七，得到最终的有序结果。

每个不在位的元素只搬一次，每个环另加一次临时变量的存取，所以整理是线性时间、常数辅助空间。顺带一提，底稿把第一个环印成了零、五、四、一，和元素对不上，应该是零、五、四、二。

## P69｜三种 n 平方排序：差别在对输入形态的反应

先看三种简单排序。平均和最坏都是 n 的平方，差别在于对输入形态的反应。直接插入和带无交换退出的冒泡，在已经有序时最好，只要线性时间，而且都是稳定的。直接选择不管输入什么样都是 n 的平方，还不稳定，但它的交换次数最少，不超过 n 减一次。

为什么它们都快不起来？原因是同一个。插入和冒泡只对相邻的两个记录做比较和移动，记录只能一步一步挪向目标位置。直接选择虽然改进了交换次数，但在剩余记录里逐个线性比较，比较次数没有降下来。只做相邻比较的算法，平均步数由逆置数决定，平均有 n 乘 n 减一除以四个逆置，所以是 n 的平方。

要想从数量级上提速，就必须摆脱这种一步一步的操作。Shell 排序跨越相邻元素做分组插入，一步能挪很远，就能达到 n 的一点五次方。具体取决于增量：每次减半的增量最坏仍是 n 的平方，Hibbard 增量最坏是 n 的二分之三次方。

## P70｜量出来的数量级

再看实测数据，用 g++ 十三点三、O2 优化、随机数据，单位是毫秒。

有两件事值得停下来看。第一，同为 n 的平方，冒泡比插入慢了二十七倍：五万个数时，冒泡五千八百多毫秒，插入只要两百一十多毫秒。常数差来自哪里？冒泡每次交换要三步赋值，插入只需一次搬移。

第二，看增长倍数。n 从一万到五万，扩大五倍。n 的平方的三个算法，时间涨了二十五到三十六倍，理论值是二十五，冒泡偏高；n log n 的三个，堆排、快排、归并只涨了四到六倍。

## P71｜对数据分布的敏感性；标准库的排序是怎么拼的

各算法对数据分布的敏感程度不一样。选择、归并、基数排序对分布不敏感；插入、冒泡、Shell 都是正序比逆序快，正序或基本有序时简单算法表现最好。原书的快排用中间点作轴，正序和逆序一样快，都比随机快；本书取末元素作轴，在这两种输入上反而最慢。堆排序逆序比正序稍快，因为建最大堆时，逆序输入已经自然成堆。顺序基数排序比链式快，但记录是较大的组合类型时，应该用链式存储来减少移动。

右边是 C++ 标准库的 sort，叫 introsort，就是本章三种算法拼起来的：主体是三点选中的快速排序；区间长度小于阈值，原书记为二十，就停下来，最后整体做一遍插入排序；递归深度超过二倍 log n，就转为堆排序，保证 n log n。所以它最坏比堆排序差一些，比快排好得多，平均与快排差不多。另外，stable sort 用的是归并，partial sort 用的是堆排序。

这也是本书不用标准库排序顶替这一章的理由：读懂它的前提，正是先把这三种都亲手写一遍。

## P72｜Python 的 Timsort：插入加归并，稳定

Python 的 sorted 和列表的 sort 方法，用的是 Timsort，本质是插入加归并，而且稳定。

它分三步。第一步找 run：从左往右切出已经有序的段，严格递减的段原地翻转，这是它在真实数据上快的根源。第二步补齐：短于 minrun，也就是大约三十二到六十四的段，用二分插入排序补长，这和八点四、八点五节小区间改插入是同一思路。第三步归并：把段压栈，按长度规则两两归并，保持各段长度平衡；归并时如果一边连续胜出，就倍增跳跃，叫 galloping。

和 introsort 比，Timsort 最好情况是线性的，已经有序或逆序的输入只要 n 减一次比较；代价是 n 的量级的额外空间。

稳定性有个直接用法：多关键字排序。右边的例子先按姓名排，再按分数降序排，同分的人会保持上一趟的姓名次序。这正是八点一节稳定的意义，和 LSD 基数排序先排低位是同一个道理。实用上，key 参数对每个元素只算一次，也可以用一个元组作 key 一次排好。OJ 里先用内置排序；本章手写，是为了知道它为什么快、什么时候不快。

## P73｜判定树：比较排序的下限

现在证明比较排序的下限。左边的图是三个元素的判定树。

分四步看。第一，每个内部结点是一次比较，问 a 的第 i 个元素是否小于 a 的第 j 个元素；每片叶子是一种输出排列；比较次数就是从根到叶的路径长度。第二，n 个互不相同的元素有 n 的阶乘种排列，每一种都必须被区分出来，所以叶子至少有 n 的阶乘片。第三，高度为 h 的二叉树最多有二的 h 次方片叶子，所以二的 h 次方大于等于 n 的阶乘。第四，取对数，h 大于等于 n 的阶乘的对数；n 的阶乘里大的那一半因子都不小于 n 的一半，所以这个对数至少是 n 的一半乘以 log 二分之 n，也就是 n log n 的量级。树高正是最坏比较次数。

下限是问题可能达到的最佳效率，上限是已知最快算法的效率。比较排序的上下限都是 n log n 量级，两者重合，不可能更快。

但要注意，这个下界只管比较排序。桶式和基数排序不做比较，站在下界管辖的范围之外，代价是值域要够密，或者位数要够少。

## P74｜手写 Python 排序的五个坑

本章总结之前，先看手写 Python 排序时最常见的五个坑，都是实测出来的。

第一，归并时写成左边严格小于右边才取左，相等时先取右边，就不稳定了，拿它数逆序对还会把相等的一对也算进去，要改成小于等于。第二，计数排序不减最小值，负数下标在 Python 里合法，会环绕到末尾，不报错却给错答案。第三，区间桶排序用最大值减最小值再除以 n 当桶宽，全部相等或只有一个元素时桶宽为零，会报除零错误，要先特判。第四，插入排序写成逐对交换、找到位置也不停，有序输入也要比较 n 乘 n 减一除以二次，最好情况的线性时间就丢了；应该用循环加后移，遇到不大于的就停。第五，快排用列表推导、首元素当轴，恰好稳定但不原地，有序输入会退化，一千个元素就递归过深报错，要改用随机轴加三路划分。

怎么防？拿随机数据和内置的 sorted 对拍，再补四类边界：空、单元素、全相等、含负数；稳定性用键加原序号的记录来测。

## P75｜九种内排序放在一张表里

这张表把九种内排序放在一起。

先看时间。平均为 n 的平方的是直接插入、直接选择和冒泡；Shell 取决于增量；堆排序、快排、归并平均都是 n log n，但快排最坏会退化到 n 的平方，而堆排序和归并最坏也有保证。桶式是 m 加 n，基数是 d 乘以 n 加 r，不过关键码互不相同时，实际上是 n log n。

再看空间。插入、Shell、选择、堆、冒泡都是常数；快排平均要 log n 的栈空间，最坏要 n；归并要 n 的量级；桶式要 m 加 n，基数要 n 加 r。

最后是稳定性，表下面一行总结得很清楚：稳定的有插入、冒泡、归并，以及分配排序里的桶式和基数；不稳定的有直接选择、堆、Shell 和快排，要说明不稳定，举一个反例就够了。

## P76｜怎么选

那么实际中怎么选？按规模、稳定性、有序程度和关键码形态来考虑。

关键码基本有序，直接插入最快，冒泡也较快。要求速度稳定、对初始排列不敏感，选归并。n 较小，几十到几千，用直接插入或直接选择。n 较大，就用 n log n 的快排、堆排序、归并或基数排序；其中输入杂乱无序、又没有稳定性要求时，快速排序效果最好；n 很大而关键码位数较少时，用静态链的基数排序。

右边是三条补充。记录很大搬不起，要减少移动，可以用索引排序，或者用交换次数不超过 n 减一的直接选择。有空间限制时，插入、选择、冒泡、Shell、堆都只要常数空间，快排平均 log n，最坏 n，归并要 n。最后，这些方法还可以组合，插入排序就常和其他方法结合使用，比如优化快排、优化归并，以及标准库的 sort。

## P79｜OJ 15265 Shell 排序

第一题，OJ 一五二六五，Shell 排序，要求用 Hibbard 增量，也就是二的 k 次方减一：一、三、七、十五，依此类推。

增量怎么生成？从 k 等于一起，只要二的 k 次方减一小于 n 就收下，再倒过来用。样例 n 等于十，得到七、三、一，一共三趟。每一趟就是步长为 gap 的插入排序，把插入排序里的步长一换成 gap 就行。

看下面的表。第一趟 gap 等于七，只比较下标零和七、一和八、二和九这三对，四和四十七、七和三十四、三和九十八都不逆序，数组不变。第二趟 gap 等于三，下标零、三、六、九这一组四、十三、零、九十八排成零、四、十三、九十八，另外两组本来有序，得到零、七、三、四、十一、十二、十三、四十七、三十四、九十八。第三趟 gap 等于一，就是普通插入排序，得到完全有序的结果。

注意，第一趟即使没变也要输出一行，题目是按趟数计行的。和八点二点二节对照，讲义里 gap 每次除以二，最坏仍是 n 的平方；Hibbard 增量相邻互素，最坏是 n 乘根号 n。

## P80｜LeetCode 75 颜色分类

LeetCode 七十五题，颜色分类，就是原书第十四题的荷兰国旗问题：数组里只有零、一、二，要一趟排好。

快排的两路划分只分小于等于轴和大于轴两段，这里要一次分成三段。用三个指针 lo、i、hi，维持下面表格里的不变式：lo 左边全是零，lo 到 i 之间全是一，hi 右边全是二，i 到 hi 之间是还没看的。每一步让还没看的部分缩小一：遇到零，换到左边，lo 和 i 都前进；遇到二，换到右边，只让 hi 后退；遇到一，直接跳过。

最容易错的是和二交换之后 i 不动。从右边换来的数还没看过，可能是零，必须再检查一次；而从左边换来的一定是一，已经看过，所以 i 可以前进。

这样是线性时间、常数空间。计数排序数一遍零、一、二再写回也是线性的，但要扫两趟。

## P81｜LeetCode 215 第 K 个最大元素

LeetCode 二一五，求数组中第 K 个最大的元素。第 K 大就是升序排列后下标为 n 减 K 的元素，用快速选择来找。

思路和快排一样先划分，区别在于划分完只进入答案所在的一侧。代码里每次随机选一个轴，做三路划分，分成小于轴、等于轴、大于轴三段；目标下标落在小于段，就去左边找，落在大于段就去右边找，落在等于段就直接返回这个轴。

为什么平均是线性时间？快排两侧都要递归，所以是 n log n；选择只留一侧，期望代价是 n 加 n 的一半加 n 的四分之一，一路加下去，大约是二 n。

两处防退化的设计：随机轴对付有序输入；三路划分对付全相等的输入，一趟就命中等于段，不会一次只缩小一个。

另一条路是用堆：维护一个大小为 K 的小顶堆，时间是 n log K。Python 里调用 heapq 的 nlargest，取最后一个即可。

## P82｜LeetCode 148 排序链表

LeetCode 一四八，排序链表。为什么链表选归并？快排、堆排都依赖随机访问，而归并只需要顺序地走两条链，正适合链表；而且合并时只改指针，不需要数组版那样 n 的量级的辅助空间。

分的时候用快慢指针找中点：慢指针一次走一步，快指针一次走两步，快指针到头时，慢指针就在中间，从这里断开，两半分别递归。合的时候用一个哑结点，比较两条链的头，小于等于就取左边的，保证稳定，最后把剩下的那条直接接上，只改指针、不搬数据。

有个细节：快指针要从头结点的下一个开始。这样只有两个结点时，慢指针停在第一个，能断成一加一；如果从头结点开始，会断成二加零，左半段原样递归下去，就无限递归了。

递归深度是 log n。题目的进阶要求常数空间，可以改成自底向上，步长取一、二、四，依此类推，两两合并。

## P83｜OJ 20018 蚂蚁王国的越野跑

OJ 二零零一八，蚂蚁王国的越野跑。排在后面的蚂蚁比前面的快，就算一次赶超，题目问一共有多少次赶超。

这和八点五节的逆序对是一回事：逆序对是 i 小于 j 而前面的大于后面的，这里要的是前面的小于后面的，也就是顺序对。把合并改成降序，数法一行都不用变。代码里对右段每个元素，先把左段中大于等于它的都输出，剩下的左段元素都比它小，每一个都被它赶超，一次加上左段剩余的个数。

相等时先放左边，速度相同的不计入，正好对应速度一样不算赶超。看输出，速度一、五、十、七、六，答案是七；一、五、五、七、六，答案是八，两个五之间不算。

## P85｜OJ 31202 这也是逆序对？

OJ 三一二零二，这也是逆序对？它就是前面留作练习的那道变形题。

第一步移项。a 的第 i 项加 a 的第 j 项，大于 b 的第 i 项加 b 的第 j 项，令 c 等于 a 减 b，条件就等价于 c 的第 i 项加 c 的第 j 项大于零。这个条件只和无序对有关，所以可以先排序再数。

看样例：a 是四、八、二、六、二，b 是四、五、四、一、三，c 就是零、三、负二、五、负一，排序后是负二、负一、零、三、五。

然后用对撞指针，i 从左、j 从右。如果两项之和大于零，那么 i 到 j 减一之间的元素都不小于 c 的第 i 项，配上 c 的第 j 项都成立，一次加 j 减 i，j 退一格；否则 c 的第 i 项配谁都不够，i 进一格。样例里，负二配五成立，加四；负二配三也成立，加三；负二配零不成立，i 前进；负一配零也不成立，结束。答案是七。

总复杂度由排序决定，是 n log n 的量级。

## P86｜OJ 27300 模型整理

最后一题，OJ 二七三零零，模型整理。它提醒我们，排序的关键往往在于按什么排。

输入是一些模型名加参数量，比如 GPT 一点三 B、Bert 三四零 M。先按最后一个连字符切开，参数量一定在最后，名称里即使带连字符也不会切错；然后按名称分组。名称按字典序输出，每个名称下的参数量要按数值从小到大排。

坑在于：如果直接按字符串排，一点三 B 小于一七五 B 小于三五零 M，十三亿会排到三点五亿前面。必须先把单位换算到同一量纲，比如 B 乘以一千，统一成 M。

这就用到 key 函数：sorted 加上换算函数作 key，每个元素只算一次，再按结果比较，比写比较函数更快也更清楚。看输出，Bert 是一一零 M、三四零 M；GPT 是三五零 M、一点三 B、一七五 B。这里的 sorted 就是八点七节的 Timsort，稳定，最坏 n log n。

## P87｜本章小结

最后用五句话收尾。

第一，面对任何一种排序，先问四个问题：比较还是分配？稳不稳定？额外空间多少？最好、平均、最坏三个时间各是多少？

第二，简单排序。插入、选择、冒泡都是 n 的平方：只做相邻比较的算法，平均逃不出逆置数，n 乘 n 减一除以四。

第三，分治排序。快排把力气花在分上，平均最快，但会退化；归并把力气花在合上，稳定，代价是 n 的量级的额外空间。

第四，稳定的来源，往往就是一个小于号：插入时相等不越过，归并时相等取左，分配时桶内保持入桶顺序；一旦有跨越式的移动，就不稳定了。

第五，下限与分配。比较排序最坏至少 n log n；桶式、基数排序靠关键码本身的结构，站到了下界之外。还要记住，同阶不等于同速。

第八章内部排序就讲到这里，下一章我们讨论外排序。谢谢大家。
