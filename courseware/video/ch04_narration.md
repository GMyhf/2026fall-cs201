## P2｜本章要回答三个问题

这一章围绕三个问题展开。

第一个问题：字符串和普通线性表差在哪里？一是元素被限定为字符集里的字符；二是操作以串的整体为对象，拼接、取子串动的都是一整段。另外还要提醒一句，C++ 里的 char 是一个字节，并不等于人眼看到的一个字符。

一句话概括：存串的类管容量与所有权，找串的算法管比较顺序，而 KMP 让目标串的下标只增不减。

## P7｜字符串：元素为单个字符的线性表

先看定义。字符串，简称串，是组成元素为单个字符的线性表。它可以是一个单词、一个句子、一篇文章，也可以是一个文件的全部内容。串中所含字符的个数叫做串的长度；长度为零的串叫空串，它不含任何字符。

既然是线性表，为什么还要单独开一章？因为在逻辑结构上，它和一般的线性表有两点区别。

第一点是数据对象。一般线性表的元素可以是任意类型 T，而串的元素被约束在字符集里，一个个都是字符。

第二点是操作对象。线性表的操作大多以单个元素为对象，比如插入一个元素、删除一个元素。而串的典型操作，拼接、复制、抽取子串、模式匹配，动的都是一整段。正因为操作对象是整段，存储方式和算法设计才有了自己的特点，这是后面两节要讲的内容。

---

## P8｜子串：一个串是不是另一个串的一段

接下来是子串的定义。设 s1 是长度为 n 的串，s2 是长度为 m 的串，m 小于等于 n。如果存在一个整数 i，i 在零到 n 减 m 之间，使得 s2 的每一个字符 b j 都等于 s1 的第 i 加 j 个字符，就称 s2 是 s1 的子串，或者说 s1 包含 s2。说白了，就是 s2 能在 s1 里从某个位置开始，原样对齐出现。

由这个定义可以推出三条：空串是所有字符串的子串；任何串都是它自身的子串；既非空、又不等于自身的子串，叫做真子串。

看右边的例子。在 The quick brown dog jumps over the lazy fox 这句话里，quick、jump、fox，还有中间带空格的 brown dog，都是它的真子串。注意 jump 只是 jumps 的一部分，也照样算，因为子串只看字符是否连续对齐，不管单词边界。

最下面的伏笔很重要：四点三节的模式匹配，问的正是一个串是不是另一个串的子串；如果是，从哪个位置开始。

## P10｜逻辑元素是字符，内存里保存的是编码单元

逻辑上，串的元素是字符；但计算机只认由零和一组成的字节，所以字符必须用字节来表示，这就是字符编码。C 和 C++ 的 char 是单字节，采用 ASCII 编码：每个字符一个字节，低 7 位表示字符，最高位为零，一共 128 个字符。

看表格。零到三十一，再加上一百二十七，共 33 个，是控制和通信专用字符，比如换行、回车、删除、响铃。注意原书把 32 号空格也算进来，得到 34，其实空格是可打印字符，只是看不见。三十三到一百二十六共 94 个通用字符，包括 52 个大小写字母、10 个数字，以及标点和运算符号。

表格下面三行最值得记：数字零到九是 48 到 57，字符零等于 48；大写字母是 65 到 90，A 等于 65；小写字母是 97 到 122，a 等于 97。

底部那句话是这一页的重点：这三个区间各自都是连续递增的。下一小节讲字符比较，就建立在这一点上。

## P11｜从各自为政到 Unicode 和 UTF-8

ASCII 是二十世纪六十年代制定的，只考虑了英文，没有考虑中文、阿拉伯文这些国际文字的统一编码。

于是各个语言只好各自编码。中文有简体的 GB2312-80，收了 6763 个汉字；繁体有 BIG5，收了 13053 个汉字；日文有 S-JIS，韩文有 Wansung。问题在于，这些编码各自为政，不同系统可能用相同的编号表示不同的字符，同一份文件换个系统打开就成了乱码。

为了解决这个问题，出现了 Unicode，也就是通用文字符号编码标准。它是可伸缩的：既能容纳多语言的大编码集，也能缩减，用单字节表示常用的 ASCII 符号。

今天最常见的落地形式是 UTF-8。它用一到四个字节来编码一个 Unicode 码点，而且和 ASCII 完全兼容，原来的 ASCII 文本本身就是合法的 UTF-8。这也正是下一页要讲的那个坑的来源。

---

## P12｜char 不等于字符

这一页讲一条 2008 年出版的原书还讲不到的结论：C++ 的 char 是一个字节，不等于一个人眼看到的字符。

在 UTF-8 下，一个汉字通常占好几个字节。所以标准库 string 的 size 函数返回的是字节数，不能拿来数 Unicode 字符。要数字符，就得按 UTF-8 规则解码，或者使用专门的 Unicode 库。字面量前面加 u8 前缀，表示这是一个 UTF-8 字节序列。

左下角有一句自检：字节数、字符数、显示宽度，是三个不同的层次，在 UTF-8 下不能混用。比如一个汉字，字节数不是一，字符数是一，而在终端里显示的宽度往往又占两格。

右边是好消息：编码本身并不改变字符串概念和操作的本质。查找、拼接、抽取子串，这些接口的语义和编码无关。所以本书和原书一样，以 ASCII 为主，基本不涉及多国语言混排。

## P13｜编码顺序与自然次序一致

现在讲字符怎么比大小。

设 encode 是把一个符号映射到它的 ASCII 编码的函数。那么十个数字符号的编码是连续递增的：字符零的编码加一等于字符一的编码，字符一的编码加一等于字符二的编码，一直到字符八加一等于字符九。大写字母 A 到 Z、小写字母 a 到 z 也遵循同样的规则。

于是，任意两个字符可以直接用编码值比较大小；对字母来说，比出来的就是字典编目的次序。两个串则按构成它们的字符，逐个比较。

右边是字典次序的例子。monday 小于 sunday 小于 tuesday，星期一排在星期二之前，这符合直觉。但是字符串 123 小于 1234，1234 又小于 23，这就和日常理解不同了：作为整数，123 比 23 大，作为字符串却更小，因为第一个字符 1 就比 2 小。

底部的比较规则请记住：先比较第一个不同的编码单元；如果一个串是另一个串的前缀，较短的那个更小。123 是 1234 的前缀，所以 123 更小。

## P14｜编码值比较不等于自然语言排序

上一页的规则要注意适用范围，这里分三点说。

第一，同一区间内可比。ASCII 保留了数字、大写字母、小写字母各自连续的区间，在同一个区间里，可以直接用编码值比较。

第二，它不是语言学排序。编码值比较按的是码元的字典序；大小写怎么排、带重音的字母怎么排、中文按拼音还是按笔画排，这些都可能需要额外的 locale 设置或者排序键。

第三，它也不是整数比较。对标准库的 string 来说，123 小于 1234 小于 23，但这显然不是整数大小。

结论是：比较之前，必须先约定编码和规范化方式，不能把字节序误当成自然语言顺序。另一方面，本节这套逐个字符比较的次序，同样适用于 GB2312 等其他文字的排序需要。

## P15｜两个字面量之间写小于号，比的是地址

再看一个 C++ 特有的坑。程序输出了两行。

第一行，比较的一边是标准库 string 对象：123 和 string 类型的 1234 比，结果为真；string 类型的 1234 和 23 比，结果也为真。这时比的是内容，答案和上一页的字典序一致。

第二行，两边都是裸的字符串字面量：123 小于 1234 得到假，1234 小于 23 得到真。第一个答案反了。为什么？因为两个字面量都是字符数组，写小于号时它们退化成指针，比的是两个数组在内存里的地址，而地址怎么摆是编译器决定的，和内容毫无关系。好在编译器给出了警告，提示这是两个数组之间的比较。

所以本书定一条规矩：凡是比较字符串，一律先落到 String 或者标准库 string 上，再谈编码顺序。

## P17｜这一节的正题：变长存储管理

这一节的正题是变长存储管理。

为什么这是个问题？字符串的长度变化非常显著，短的只是一个单词，长的是整个文件，长度分布的方差很大。这时用一个静态长度的向量作为存储结构是不恰当的：开小了装不下，开大了又浪费。而拼接、查找、置换、模式匹配这些操作，本身都涉及长度的变化，开销大，必须精心设计算法、选择存储结构。所以本节的重点就是：程序执行过程中，字符串的变长存储问题。

右边解释了为什么这一节没有 Python 版。我们要写的对象，是一个自己管理的字符缓冲区：长度、容量、结尾空字符、深复制、移动之后源对象处于什么状态，都是接口契约的一部分。而 Python 的 str 不可变，list 也不让你自己去分配、释放、实现强异常保证，用 Python 写就会跳过存储布局和所有权这些问题。所以四点三节的模式匹配有 Python 版，四点二节的字符串类只保留 C++。

左下角那句话再强调一遍：缓冲区是裸的字符指针，换成标准库的 string，这一节就没了。

## P18｜顺序存储：连续字符数组加结尾的空字符

先看最朴素的顺序存储，也就是 C 风格字符串。

图 4.1 里有三个数组。s1 长度为 12，存的是 Hello world，十一个字符占下标零到十，下标十一放结束符，也就是反斜杠零。s2 长度为 8，存的是 2008，四个字符之后在下标四放结束符，后面的空间没有用。s3 长度为 6，没给初值。注意左下角的提醒：只有全局或 static 数组才会自动成为空串，局部数组的内容不确定，想要空串就明确写等于一对空引号。

右边是几个要点。末尾保留一个空字符作为结束标志，另外记录不含终止符的长度。所以容量至少是长度加一，空字符不计入长度，一个长度为 M 的字符数组，能放的串长不超过 M 减 1。按下标取第 i 个字符是常数时间；但插入和删除要移动后面所有字符，拼接和取子串要复制一段连续区域。容量不足时，只能申请更大的数组，复制过去，释放旧数组，再更新指针和长度。

右下角点出了静态定长的局限：数组一旦定长，运行中产生更长的串就会溢出。这正是接下来要用一个类来解决的问题。

## P19｜表 4.1：标准串函数

表 4.1 列出了头文件 cstring 里常用的标准串函数。

strlen 求串的当前长度，不计结束符，空串的长度为零。strcpy 把第二个串复制到第一个串，返回指向第一个串开头的指针。strcat 把第二个串拼接到第一个串的尾部。strcmp 比较两个串：完全相同返回零，第一个大于第二个返回正数，小于返回负数。注意，标准只规定了符号，没有规定具体是多少，这一点后面讲 compare 时还会用到。strchr 定位某个字符在串中第一次出现的位置，strrchr 则从尾部逆向找最后一次出现的位置，两者找不到时都返回空指针。

这些函数有一个共同前提：调用方自己保证目标数组足够大。strcpy 和 strcat 都不检查容量，写过界就是缓冲区溢出。

底部补充一句：输入输出也属于标准串函数库，用 cin 可以把一个字符串读进字符数组，用 cout 可以把它输出。

## P20｜strchr 和 strrchr 返回指针；s1 等于 s2 不是复制

图 4.2 演示在 s1，也就是 Hello world 中定位字符 o。字母 o 出现了两次：一次在下标 4，是 Hello 的最后一个字母；一次在下标 7，是 world 的第二个字母。strchr 从左往右找，箭头指向下标 4；strrchr 从右往左找，箭头指向下标 7。

注意它们返回的是指针，不是下标。左下角讨论「没找到」怎么表达：这两个函数找不到时返回空指针。本书的 String 改用下标加 optional 来表达同一件事，「没找到」不再依赖一个特殊的指针值。

右下角是一个非常容易犯的错误。C++ 里字符数组是用字符指针指向它的起始地址的，所以对两个字符指针写 s1 等于 s2，并不是把 s2 的内容复制到 s1，而只是让 s1 指向和 s2 同一块内存。两个变量共用一块缓冲区，改一个另一个也跟着变，释放时还可能释放两次。这正是我们的 String 类必须自己写拷贝赋值运算符的原因。

## P21｜变长存储为什么不走链表

既然要支持变长，自然会想到链表：每个结点放一个字符，想多长就多长。左边就是这种链式存储，H、e、l，每个结点后面跟一个 next 指针。

问题出在空间上。一个字符只占 1 个字节，而在 64 位机上一个指针要 8 个字节，每一个链指针比它所服务的字符还大得多。回想第二章二点四节的判据：指针所占比例超过一比一，就要慎重。这里远远超过了，所以链式存储不划算。

右边是我们的选择：仍然顺序存放，但交给一个类去管。类里只存两样东西，一个指针和一个长度；图中指针指向堆上的一段连续数组，里面是 H、e、l、l、o 和结尾的空字符，长度记为 5。

底部这一行是关键。顺序存储只回答了「字符放在哪」；包成类之后，「这块内存归谁、什么时候还」才有了着落：构造时申请，析构时释放，拷贝时另开一份。

## P22｜空串也占 1 个字节；从 C 字符串构造

现在开始看教学版 String 的代码，一共分五页。

右上角列出了两个数据成员：一个字符指针，指向以空字符结尾的数组，而且永远非空；一个长度，记录字符个数，不含结尾的空字符。

先看默认构造函数，它构造的是空串。注意，它仍然申请了 1 个字节，里面放一个空字符。为什么空串也要申请？这样 c_str 函数永远返回一个合法的 C 字符串，调用方不必先判断是不是空指针。

再看从 C 字符串构造。参数是指向常量字符的指针，而不是原书的普通字符指针，原因下一页细说。函数先检查空指针，如果是空指针就抛出无效参数异常；然后用 strlen 求长度，申请长度加一个字节，用 memcpy 把内容连同结尾的空字符一起拷过来，所以拷贝长度也是加一。

这个构造函数故意没有加 explicit，为的是保住 String s1 等于 Hello 这种写法，也就是第四页演示过的隐式转换。最后是析构函数，用数组形式的 delete 释放缓冲区。

## P23｜原书算法 4.4 的构造函数：两处问题

原书的构造函数有两处问题。

第一处，原书写了一句断言，判断指针不等于反斜杠零，这句编译不过。反斜杠零是一个 char，不是空指针常量，拿指针和它比较在 C++ 里是不合法的。就算改成判断不等于 nullptr 也没用：如果担心的是 new 失败，new 失败会抛出 bad_alloc 异常，从来不返回空指针。何况 assert 在定义了 NDEBUG 的发布构建里整个消失。

第二处，参数类型是普通的字符指针。原书自己写了 String s1 等于 Hello，说它会隐含调用这个构造函数。可是字符串字面量的类型是 6 个常量字符组成的数组，把它转成非常量的字符指针，从 C++11 起就已经被移除了。GCC 默认把它降级为警告，但在本书开启 Werror 的构建下就是错误。

底部还有一处原书没做的检查：构造函数对传入空指针毫无防备，而四点二点三节原书的 Substr 恰好会喂给它一个空指针。本书的做法是参数用指向常量字符的指针，遇到空指针抛出无效参数异常。

## P24｜三法则：拷贝构造与拷贝赋值

第二页讲三法则：一个类如果自己管着 new 出来的缓冲区，那么析构、拷贝构造、拷贝赋值这三个函数都必须自己写。原书正文描述过赋值时必须释放原有空间，却没有把拷贝构造和拷贝赋值作为清单给出。只有析构而没有这两个，一句 String b 等于 a，两个对象就共用同一块缓冲区，析构时释放两次。

拷贝构造比较直接：按对方的长度加一申请新数组，再把内容连同空字符一起拷过来。

拷贝赋值要多想一步。先判断是不是自己赋给自己，是就直接返回。然后看下方的三步顺序，代码里红色的两行就是关键：第一步，备好新的，申请新数组并拷入内容；第二步，释放旧的；第三步，接管，让数据指针指向新数组，并更新长度。

为什么一定是这个顺序？看右下角。如果顺序反过来，先释放旧的再申请新的，一旦 new 抛出异常，对象就停在指针已释放的破碎状态，之后析构时又会再释放一次。先备新、再释放，保证任何时候失败，原对象都完好无损。

## P25｜图 4.3 和 4.4：按当前串长动态调整空间

两张图把变长管理画得很直观。

左边是图 4.3，String s1 等于 Hello。在动态存储区开一个长度为 6 的字符数组，5 个字符加一个结束符。对象本身里只有一个指针和一个长度 5，字符本体在堆上。

右边是图 4.4，先构造 s2 等于 Hello world，再执行 s1 等于 s2。新内容有 11 个字符，原来那块 6 个字节的空间装不下，于是另开一块 12 个字节的新数组，把 Hello world 和结束符复制过去；图上方那块灰色的旧数组被释放，s1 的指针改指新数组，长度改成 11。

底部请注意那块灰色的旧空间：它必须释放，否则就是内存泄漏；而且必须在新空间准备好之后再释放，这就是上一页那个三步顺序。这就是变长管理的全部含义。工程版还多两个移动操作，放在四点二 a 节讲。

## P26｜访问器、clear 与 at

第三页是几个访问器。

size 和 length 是两个名字，返回同一个值：字符个数，不含结尾的空字符。empty 判断长度是否为零，返回 bool，对应原书那个返回 int 的判空函数。c_str 直接返回内部的数据指针。

clear 值得一看。它不是简单地把数据指针置空，而是换成一块只装一个空字符的 1 字节缓冲区。这样 c_str 永远非空这个不变式依然成立。而且它的写法同样是先备新、再释放：先申请新的 1 字节，再释放旧的，最后接管并把长度清零。

at 按下标取字符。如果下标大于等于长度，就抛出越界异常，而不是返回一个随便什么值。原来的 C 数组越界不会报错，只会悄悄读到别处的内存，这里把错误显式地暴露出来。

左下角提醒：按下标取字符是常数时间，这是顺序存储的长处。

## P27｜追加一个字符：为什么是 O(n)

第四页是追加一个字符，也是变长存储的代价看得最清楚的地方。

看右边的三步图，以给 Hello 追加感叹号为例。第一步，申请一块新数组，大小是原长度加二，因为要放老内容、新字符和空字符，图中是 7 个空格子。第二步，拷贝：先把 Hello 五个字符拷过去，再放上感叹号，最后补上空字符。第三步，释放旧块，也就是原来装着 Hello 和空字符的那 6 个字节。最后让指针接管新数组，长度加一。

所以，字符串长度一变，就得重新申请、拷过去、还回去，追加一个字符要拷 n 个字符，代价是 n 的量级，而不是常数。右下角说，这也是后续章节讨论预留容量的动机：预先多留点空间，就不必每次都重新申请。

左下角讲返回值。append 返回对本串的引用，于是可以连着写 append a 再 append b，而且从签名一眼就能看出改的是本串。原书代码四点一按值返回，调用一次 append 到底改没改原来的串，从签名上看不出来。

## P28｜concatenate：重新申请、拷两段、释放旧的

concatenate 把一个 C 字符串接在本串后面，套路和 append 一样：重新申请、拷两段、释放旧的。

代码先检查空指针，是空指针就抛出无效参数异常。然后用 strlen 求出要追加的长度，记作 extra，申请原长度加 extra 加一的新数组。

看右边的图，以 Hi 逗号接上 C++ 为例。第一段 memcpy 把原来的三个字符 H、i、逗号拷到新数组开头；第二段从偏移原长度的位置开始，拷入 C、加号、加号，拷贝长度是 extra 加一，多出来的那一个正好把 s 结尾的空字符一起带上，省得再单独补。之后释放旧数组，接管新数组，长度加上 extra。

底下的表格把三种运算的代价放在一起。append 申请长度加二，拷原长度个字符，是 n 的量级；concatenate 拷两段，是 n 加上 s 的长度的量级；at 直接按下标取，是常数时间。修改长度的运算都要付出复制的代价，只有按下标读才是顺序存储真正的便宜之处。

## P29｜抽取子串，算法 4.5：越界就抛

第五页上半部分是抽取子串，对应原书算法四点五：从 pos 开始，取长度至多为 len 的子串。

代码先检查起始位置。如果 pos 大于当前长度，就抛出越界异常。然后算出从 pos 到末尾还剩多少字符，实际取的个数是 len 和剩余长度中较小的那个，这和原书「如果 n 大于剩余就令 n 等于剩余」是同一个意思。接着构造一个空的结果串，为它申请实际长度加一的空间，从原串偏移 pos 的地方拷过来，补上空字符，再把结果串原来那 1 字节的缓冲区释放掉，接管新数组。

底部三个框把边界情况讲清楚。pos 大于长度，抛出越界异常；pos 正好等于长度，是合法的，得到空串，可以理解为从末尾取 0 个字符；len 超出剩余长度，截断，不报错。

为什么原书在这里需要改？下一页就会看到，原书越界时的处理会让程序直接崩溃。

## P30｜原书越界时 return NULL：能编译，崩在运行期

原书的 Substr 在起始位置越界时，写的是返回 NULL。这句能编译，但会崩在运行期。

看上方的输出。调用 Substr，起始位置 99，取 1 个字符，程序走到返回 NULL 那一支，随即报告空指针被传给了一个声明为不能为空的参数，接着 AddressSanitizer 报告段错误。

中间这条链路解释了原因。函数的返回类型是 String，返回 NULL 并不是返回一个空串；NULL 会被当作字符指针，于是去调用以字符指针为参数的构造函数；构造函数对空指针毫无防备，直接调用 strlen，对空指针求长度，当场段错误。

左下角是本书的做法：越界抛出越界异常，让错误停在发生的地方，而不是变成调用方某处莫名其妙的段错误；构造函数也对空指针设防，抛出无效参数异常。

右下角重申两条合法边界：pos 等于长度合法，得到空串，与从末尾取 0 个字符的直觉一致；len 超出剩余长度时截断，与原书的语义一致。

## P31｜find，算法 4.4：optional 取代负一

find 对应原书算法四点四：从 start 开始查找字符 c。

代码很简单：从 start 往后逐个比较，遇到相等就返回当前下标；循环结束还没找到，返回一个空的 optional。

关键在返回类型。左边是原书的写法：返回 int，用负一表示没找到。下面那段示意代码，先 find 一个 x，然后直接拿结果去 at，忘了判负一。负一和「位置 0」只差一个符号，漏判就把「没找到」当成「匹配在开头」，或者干脆拿负一去当下标。

右边是本书的写法：返回装着下标类型的 optional。调用时在 if 里接住结果，有值才解引用使用。找到了，盒子里是下标；没找到，就是一个空盒子，根本拿不出数字来误用。

右下角提到，这和第二章二点二点二节的 getPos 是同一个问题、同一个改法。用一个特殊值同时表示「结果」和「失败」，是很多老代码的通病。

## P32｜compare，算法 4.3：只该看符号

第五页下半部分是比较，对应原书算法四点三。

compare 是三路比较：返回负数、零、正数，分别表示小于、等于、大于。实现只有一行，直接调用标准的 strcmp。代码下方是两个私有数据成员，再往下用 compare 定义了三个关系运算符：等于、不等于、小于，分别判断 compare 的结果是否等于零、不等于零、小于零。

左下角说的是原书的问题。原书自己实现了一个 strcmp，返回值固定为负一、零、一，还在正文里说这与 C 和 C++ 通常的大小比较习惯不一致。其实不一致的是原书自己：标准 strcmp 返回的就是差值的符号，调用方只该看符号，不该看具体数值。表 4.1 讲过，标准只承诺正数、零、负数。

右下角是本书的做法：保持标准语义，并据此提供等于、不等于、小于这几个关系运算符。另外顺带澄清一点：原书那个和标准库同名同签名的 strcmp，实测能编译也能链接，并不构成冲突。

## P33｜工程版的拷贝：读 raw，copy-and-swap

接下来是进阶的选读内容，工程版 modern.hpp。

先看拷贝构造。和教学版几乎一样，但红色那一行有个细节：拷贝时读的是对方的 raw 函数，而不是直接读对方的数据指针。为什么？左下角解释：源对象可能是被移动过的对象，它的数据指针是空的。从空指针 memcpy，哪怕长度是 0，也是未定义行为。raw 在指针为空时会返回一个空串，读取就安全了。

再看拷贝赋值，换成了拷贝并交换的写法：如果不是自赋值，先把对方拷成一个局部对象，再和自己交换。交换之后，局部对象带着原来的旧缓冲区离开作用域，自动释放。

右下角总结了它的好处。第一，自赋值也安全。第二，拷贝发生在局部对象上，如果拷贝失败抛出异常，原对象根本还没被碰过，不受影响，这就是强异常保证。和教学版的先备新、再释放是同一个思想，只是借助交换写得更简洁。

## P34｜移动之后的那个空壳怎么办

工程版还多了两个移动操作。

移动构造不分配内存：直接接管对方的缓冲区和长度，再把对方的指针置为空、长度置为零。移动赋值也一样：如果不是自己，先释放自己的旧缓冲区，接管对方的，再把对方置空。

右上角说，移动操作声明为 noexcept，也就是保证不抛异常，所以不能在里面分配内存，因为分配可能失败。被移动方的数据指针只能置为空。如果在这里 new 一块空缓冲区去修复对方，移动就不再是 noexcept 的了。

可这样一来，教学版那条承诺，c_str 永远不是空指针，就被打破了吗？右边第二个框回答：可承诺不能作废。工程版加了一个私有的 raw 函数，数据指针为空时返回一个静态的空串，所有读取路径都走它，不花任何分配。这样被移动方仍然是一个可用的空串。

最底下补充，其余差别和前几章相同：加了 nodiscard 标注、noexcept、拷贝并交换，大于、小于等等全部关系运算符都由 compare 派生。

第三部分，模式匹配，这是本章的重点。先讲朴素匹配和原书差 1 的问题，再讲特征向量 next、KMP 与线性论证，最后用 KMP 求最小循环节。

## P36｜在很大的文本里找一个短小的模式

模式匹配，就是在文本中寻找给定的模式。通常的情形是文本很大，模式短小。

举两个应用。左边是文本编辑：做替换之前，先得找到被替换的内容。这时模式大约是一个单词，十个字符左右；文本则从几百字到上百万字不等。

右边是 DNA 分析。遗传信息由 A、C、G、T 四个符号组成。模式是一个基因，一般几百个字符；而文本是人类的单倍体基因组，约三十亿个碱基对。

这些应用对匹配算法的效率要求很高。底部这句话请记住：在三十亿个字符里，T 的长度乘以 P 的长度的量级，和 T 的长度加上 P 的长度的量级，是两个世界。模式长几百，前者就比后者大几百倍。前一种是朴素匹配的最坏情况，后一种是 KMP 能做到的，这一节就是要从前者走到后者。

---

## P37｜精确匹配与近似匹配；本节的记号

匹配分两大类。

左边是精确匹配：T 中至少有一处与 P 完全相同才算成功，差一个字符也算失败。精确匹配可以是单选，比如找 set；也可以是多选，比如 s 问号 t 可以匹配 sat、set、sit，这个问号叫通配符，更复杂的情形用正则表达式。

右边是近似匹配：P 与 T，或者 T 的某个子串，存在某种程度的相似就算成功。常用的相似度，是把一个串转换成另一个串所需的插入、删除、替换的操作次数。

本节和原书一样，只讨论精确匹配中的单选情况。给定 T 和 P，要在 T 中找一个位置 j，使得 P 的第零个到第 m 减 1 个字符，逐个等于 T 从第 j 个开始的 m 个字符。

最下面这句请特别记住：P 和 T 的第一个字符都从位置 0 开始。四点三点一节会看到，原书自己的两个算法都没有遵守它。另外，我们的实现用 string_view 接收输入，它只是一个视图，不拷贝，也不拥有。

## P38｜naive_search：接口与约定

先看朴素匹配的接口。函数接收文本和模式两个 string_view，返回模式在文本中首次出现的起始下标；没有出现就返回空的 optional。

函数开头处理两个边界：模式长度为零时返回 0；文本比模式短时，直接返回空。

下面三个框是三条约定。

第一，返回值是起始下标，找不到时返回空，用 optional 取代原书的 int 加负一。

第二，空模式返回 0。这和标准库 string 的 find 查找空串的行为一致：空串是任何串的子串，出现在开头。原书用断言要求模式长度大于零，把空模式挡在门外，可断言在 NDEBUG 下会被整个编译掉，等于没挡。

第三，原书差 1。原书成功时返回 j 减模式长度再加 1，而在从零开始的下标体系里，正确的是 j 减模式长度。注释里也提到了证据：用书中自己的例子，匹配始于下标 10，原书返回 11。

## P39｜朴素匹配：失配就右移一位，从头再比

接着看算法主体。两个下标：i 是模式下标，j 是目标下标，都从零开始。循环条件是模式还没比完、目标也还没走完。

思路见右上角：把模式的首字符依次对齐目标的每一个位置，逐字符比较。如果当前字符相等，i 和 j 都加一，继续往后比。如果失配，模式相对 T 右移一个字符，重新开始下一趟：i 归零，j 退回到本趟起点的下一个位置。

这个回退就是红色那一行，j 等于 j 减 i 加 1。本趟已经匹配了 i 个字符，j 减 i 就是本趟的起点，再加 1 就是下一个起点。这里的加 1 是对的，意思是换一个起点重来。

循环结束后，如果 i 已经走到模式长度，说明配上了。此时 j 已经走到匹配段末尾之后，所以起始位置是 j 减 m，不需要再加 1。

左下的表格把两个下标的行为对照列出。相等时，两者都加一；失配时，i 归零，j 回溯。注意 j 会往回退，这就是目标串下标的回溯，也是朴素匹配慢的根源。

## P40｜Python 版：同一个回溯过程

Python 版和 C++ 版逐行对应：空模式返回 0，两个下标，失配时 j 等于 j 减 i 加 1，成功时返回 j 减模式长度，全都一样；找不到时返回 None。

有一点小区别：C++ 版先判断文本是否比模式短，短就直接返回空；Python 版不必单独判断，循环条件会让它自然结束，返回 None。

下面手算一个例子：T 是 abababd，P 是 ababd。

第 1 趟从起点 0 开始。T 的前四个字符 abab 和 P 的前四个字符逐一相等，比到第五个字符时，T 是 a，P 是 d，失配。这一趟比较了 5 次，j 从 4 退回到 1。

第 2 趟从起点 1 开始，T 的第 1 个字符是 b，P 的第零个字符是 a，一上来就失配，只比较 1 次，j 退到 2。

第 3 趟从起点 2 开始，T 从下标 2 到 6 正好是 ababd，五个字符全部相等，比较 5 次。此时 j 走到 7，返回 7 减 5，等于 2。

三趟合计比较 11 次。注意第 1 趟已经比过的 T 的第 2、3 个字符，第 3 趟又比了一遍，这就是重复比较。

## P41｜图 4.6：朴素匹配逐趟过程

## P42｜三种极端情况：图 4.7、4.8、4.9

朴素匹配要比多少次，取决于输入。这里看三种极端情况，T 的长度和 P 的长度分别简称为 T 长和 P 长。

最好的情况，见图 4.7：目标开头那一段就是配串，第一趟就成功，只比 P 长次，是 P 长的量级。

失败中的最好，见图 4.8：T 全是 a，P 全是 b，每一趟在模式首字符就不等，每趟只比一次，一共大约 T 长减 P 长加 1 次，是 T 长减 P 长加 1 的量级。

最坏的情况，见图 4.9：T 形如 n 个 a，P 形如 m 减 1 个 a 后面跟一个 b。每一趟都要把前面的 a 全部比完，比到最后一个字符才失配，然后只右移一位，从头再来。总共要比 P 长乘以 T 长减 P 长加 1 次，是 T 长乘以 P 长的量级。

底部说明了最坏情况出现在哪里：这类输入很少出现在自然语言文本中，却经常出现在 DNA 信息和图像信息中，因为那里的字母表小、重复片段多。这正是需要 KMP 的实际理由。

## P43｜平均情况：依赖字符的分布概率

那平均情况呢？这依赖字符的分布概率。假设串里只允许两种字符，每种出现的概率都是二分之一，考察第 j 趟扫描。

看表格。本趟只比 1 次就失配，概率是二分之一；比 2 次，概率是四分之一；一般地，比 k 次，k 小于 P 长，概率是 2 的负 k 次方。比满 P 长次的概率是 2 的 1 减 P 长次方，因为前面 P 长减 1 位都得相等，而最后一位相等还是不等，都算比满。

据此算出，每趟平均比较次数是 2 减去 2 的 1 减 P 长次方，小于 2。总平均比较次数是 2 乘以 T 长减 P 长加 1，小于 2 倍的 T 长。

左下角是勘误 E24。第一，原书在比满 P 长次的那一项，只算了最后一位不等的情形，漏掉了配上的一半。第二，原书给出 2 的 P 长加 1 次方减 2 作为更好的比较次数，其实那个公式算的不是比较次数，而是全 a 型模式首次出现的期望位置。比如模式 00，平均要读到第 6 个字符才首次出现；而 01 只要 4 个。

右边的结论是：平均情况下朴素算法其实不慢，真正的问题是最坏情况，而最坏情况在 DNA、图像里并不罕见。

## P44｜原书算法 4.6、4.8 的返回值差 1

## P45｜朴素匹配的问题：目标的回溯

把返回值的错误放到一边，我们再看朴素匹配本身慢在哪里。

它的毛病是：一旦失配，不管模式长什么样，都只把模式右移一位，然后目标串退回去重新比。看图上的例子。第一趟，P 从 T 的位置 0 开始，前五个字符 a、b、a、c、a 都相等，到 P5 和 T5 失配。第二趟，模式右移一位，拿 P0 去比 T1。

这次比较其实是多余的。为什么？上一趟里 T1 已经和 P1 比过，二者相等；而看模式自身，P1 是 b，P0 是 a，P1 不等于 P0。两条一合，P0 不等于 T1 是直接推得出来的，根本不用再比。

Knuth、Morris 和 Pratt 三位发现：失配以后到底该右移多少位，这个数是存在的，而且和目标串无关，只依赖模式本身。所以可以预先算好，这就是特征向量。用它改进朴素匹配，就得到了 KMP 算法。

## P46｜已经匹配上的那一段携带了信息

来看一个具体的例子。T 是 abababd，P 是 ababd，从 T 的位置 0 开始比。

左边是朴素算法。前四个字符 abab 都对上了，到 T4 是 a、P4 是 d，失配。朴素算法把模式右移一位，从 T1 重新比，前面已经比过的字符又要比一遍。

右边是 KMP 的做法。已经匹配上的 abab 本身就携带了信息：它的前缀有 a、ab、aba，后缀有 b、ab、bab，最长的相同一段是 ab，长度为 2。这说明模式开头的 ab，恰好和刚才匹配段末尾的 ab 一样。所以模式可以一次右移 4 减 2，也就是 2 位，前两个字符已知相同，图中标成灰色，不用再比，直接从 P2 对 T4 继续往下比，最后在位置 2 匹配成功。

请注意右下角的关键一句：整个过程中，T 的下标从来没有往回退过。这正是 KMP 和朴素算法的根本区别。

## P47｜特征向量：失配时该退到哪里

把每个位置失配时模式该退到哪里，对模式的每一个位置都预先算出来，这组数就叫特征向量，也叫 next 数组。

左边是上例用本章实现跑出来的结果。ababd 的 next 是负 1、0、负 1、0、2；KMP 查找返回 2，和标准库 find 的结果一致。

右边的表里，next 的第 4 项等于 2，意思是在 P4 处失配时，模式的比较位置退到 2，正好和上一页手推的一致。再看等于负 1 的位置，它表示连 P0 都不必再比了，模式整体越过当前目标字符：模式下标变成负 1，下一步两个下标同时加 1。

还有一点很重要：next 只依赖模式。同一个模式算一次，就可以在任意多个目标串上反复使用。

右边绿框提醒一句：这里印的是原书算法 4.7 的优化版 next，所以中间会出现负 1。未优化的版本取值不同，但失配后的落点是等价的。

## P48｜build_next：只改了所有权

接下来看求特征向量的代码。本章的 build_next 对应原书算法 4.7 的优化版，计算过程一字未改，改的只是所有权。

原书的写法是一个返回整型指针的函数，内部用 new 申请一个长度为 m 的裸数组返回出去。问题是，书中调用它的地方一次都没有配对的 delete，每匹配一个模式就泄漏一个数组。

本书改成返回一个 vector，容器自己拥有内存，用完自动释放。另外还处理了空模式：空模式直接返回空向量。原书在这里用的是断言 m 大于 0，可断言在发布构建里会被编译掉，于是申请一个长度为 0 的数组，再往第 0 个位置写负 1，就成了一次越界写。

代码上半部分就是这些准备工作：取模式长度，空模式提前返回，然后把 i 置 0、k 置负 1，并让 next 的第 0 项等于负 1。

## P49｜用模式串跟自己匹配

下半部分是核心递推，思路是让模式串跟自己匹配。

外层循环里有一个内层 while：当 P 的第 i 个字符和第 k 个字符不相等时，就令 k 等于 next 的第 k 项，也就是沿着已经算好的特征值往回退，直到能延长匹配，或者 k 退到负 1 为止。然后 i 和 k 各加 1。

最后那一行三目表达式，就是优化所在。如果 P 的第 i 个字符和第 k 个字符相等，那么在 i 处失配时退到 k，必然会在同一个字符上再失配一次。与其白白多比一次，不如直接借用 next 的第 k 项，一步到位；不相等时，才老老实实写 k。

可以这样理解：内层 while 负责找到最长的相同前后缀，三目表达式负责跳过注定失败的落点。

## P52｜KMP 接口：next 由调用方传入

有了特征向量，就可以写 KMP 匹配了。先看接口。

kmp_search 接受三个参数：目标串、模式串，以及事先算好的 next。为什么要把 next 作为参数传进来，而不是在函数里面自己算？因为同一个模式只需要算一次 next，就能在多个目标串上复用。这正是原书强调的性质，接口把它显式地表达了出来。

函数开头做了几件防御性的检查。空模式直接返回位置 0；如果传进来的 next 长度和模式长度不一致，就抛出非法参数异常，避免用错了表还浑然不觉；目标串比模式还短，就直接返回空，表示找不到。

返回值和前面的朴素匹配一致，用可选值代替负 1，同时也修正了原书算法 4.8 里同样的差一错误。

## P53｜与朴素算法只差失配那一步

下半部分是匹配主循环。模式下标 i 可以退到负 1，目标下标 j 只增不减，代码注释里写得清清楚楚。

循环体只有两个分支。如果 i 等于负 1，或者当前目标字符和模式字符相等，i 和 j 同时加 1；否则，令 i 等于 next 的第 i 项。循环结束时，如果 i 已经走到模式末尾，就返回 j 减 m，否则返回空。下面还有一个便利重载：模式只用一次时，函数自己把 next 算好再调用。

底下这张表是整页的要点。失配时，朴素匹配把模式下标置 0，目标下标退回到 j 减 i 加 1，也就是回溯；KMP 则让模式下标等于 next 的第 i 项，目标下标不动，只增不减。两个算法的差别，就集中在失配这一步。

## P54｜Python 版 KMP

Python 版的 kmp_search 写法完全对应。如果调用时没有传 next，就现场调用 build_next 算一个；如果传了，就先检查长度是否和模式一致，不一致就报错。

看标红的两行。第一行是判断条件：i 等于负 1，或者目标字符和模式字符相等。i 等于负 1 这个分支是什么意思？next 值为负 1，表示连 P0 都不必再比，下一步 i 和 j 同时加 1，模式整体越过当前的目标字符。第二行是失配时的处理，i 退到 next 的第 i 项。

## P55｜逐步追踪 abababd 中找 ababd

我们用前面的例子把 KMP 逐步追踪一遍，next 是负 1、0、负 1、0、2。

前四次比较，a、b、a、b 都相等，i 和 j 一起走到 4。第五次比较，T4 是 a，P4 是 d，失配。这时 i 等于 next 的第 4 项，也就是 2，j 不动。第六次比较 T4 的 a 和 P2 的 a，相等；第七次 b 对 b，第八次 d 对 d，都相等。此时 i 等于 5，等于模式长度，返回 j 减 m，等于 2。

右边对比一下比较次数。KMP 一共 8 次，j 的序列是 0、1、2、3、4、4、5、6，从不减小。朴素算法要 11 次：第 5 次失配后 j 从 4 退回 1，在 T1 又失配一次，然后从 T2 开始重新比完 5 个字符。

## P56｜为什么 KMP 是线性的

KMP 为什么是线性的？可以分四步论证。

第一，j 只增不减，加 j 的语句至多执行 T 的长度那么多次；i 的自增和它在同一个分支里，也不超过这个次数。

第二，能让 i 减少的只有 i 等于 next 的第 i 项这一句，而 next 的第 i 项总是小于 i，所以每执行一次，i 至少减 1。

第三，i 减到负 1 以后，下一步必然进入同时加 1 的分支。

合起来，i 回退的次数，不会超过 i 前进的次数再加 1，所以循环体至多执行 T 长度的两倍再加 1 次。

因此 KMP 整体是 P 长度加 T 长度的量级：算 next 是 P 长度的量级，匹配是 T 长度的量级。

右下角是一条能检出退化的测试：T 是 20 万个 a，P 是 1999 个 a 再加一个 b。KMP 瞬间完成；不按特征值回退的实现会退化成两个长度相乘的量级，直接撞上超时闸门。

## P59｜KMP 的另一个用途：最小循环节

特征向量算出来的那个量，也就是前缀里最长的相同前缀与后缀，还能回答另一个问题：一个串最短是由多长的一段反复拼成的？上机考试常见的循环串、字符串乘方、前缀中的周期这三类题，核心都是这件事。

先给两个定义。真边界，是既是 s 的真前缀、又是 s 的真后缀的子串，比如 abab 的真边界有 ab 和空串。周期：正整数 p 是 s 的周期，当且仅当对所有满足条件的 i，s 的第 i 个字符都等于第 i 加 p 个字符。

定理是：s 有长为 b 的真边界，当且仅当 n 减 b 是 s 的周期。所以最小周期等于 n 减去最长真边界的长度。

证明其实就是同一组等式的两种读法。长为 b 的前缀等于长为 b 的后缀，逐位写开，就是每个字符等于它后面第 n 减 b 个字符，这恰好是周期的定义。边界越长周期越短，最长的边界对应最小的周期。

---

## P60｜三个例子：周期不一定整除长度

看三个例子。

abcabcabc，最长真边界是 abcabc，长度 6，最小周期 9 减 6 等于 3。3 整除 9，所以它是 abc 重复 3 次。

ababa，最长真边界是 aba，最小周期 5 减 3 等于 2。但 2 不整除 5，所以它有周期 2，却不是某个串的整数次重复。

abcd，没有非空的真边界，最小周期就是 4 减 0，等于 4。

下面的表格把对应的函数输出列了出来。比如 aaaa，每个前缀的边界长度依次是 0、1、2、3，最小周期是 1，是循环串，重复 4 次。而 ababa 和 abcd 都不是循环串，重复次数记为 1。

这三个例子要记住的结论是：周期不一定整除长度，判断循环串时必须单独检查整除。

## P61｜border_lengths：去掉优化的失效函数

求周期用的函数叫 border_lengths。它的第 i 项，是前缀 s 从 0 到 i 这一段的最长真边界长度。

它其实就是 build_next 去掉优化那一步之后的数，只是下标错开了一位，而且没有负 1：未优化的 next 第 i 加 1 项，等于 border 的第 i 项。

看代码。对每个 i，先取上一个前缀的最长边界长度 k，试着把它延长一个字符；如果延长不了，就令 k 等于 border 的第 k 减 1 项，退到边界的边界再试。这个回退动作，和 build_next 里沿 next 回退是同一个动作，回退链一模一样。能对上就把 k 加 1，最后记下来。

整个串只算一遍，代价是 n 的量级。注释里还特别强调了一句：求周期不能拿 build_next 代替它。为什么？下一页就讲。

## P62｜陷阱一：优化版 next 不能求周期

陷阱一：原书的优化版 next 不能拿来求周期。

原因在于优化那一步是专为匹配设计的：当两个字符相等时，退到 k 注定再失配，于是直接跳过这个落点。对匹配而言，那个落点没用；可对周期而言，它恰恰就是答案。

看 aaaa 这个例子。优化版的 next 四项全是负 1，因为每个位置都能被跳过；而 border 依次是 0、1、2、3。

求前缀 aaa 的周期。用优化版算，得到 3 减负 1 等于 4，比前缀本身还长，显然错了。用 border 算，是 3 减 2 等于 1，这才对。

这不是个别串的巧合。在 a、b 两个字母上，长度不超过 10 的全部串、全部前缀都统计过，优化版给出错误周期的前缀数以千计。所以求周期，一定要用 border_lengths。

## P63｜minimal_period 与 is_repetition

有了 border，最小周期就很简单了：n 减去整串的最长真边界长度。空串约定返回 0。

判断是不是循环串，也就是 is_repetition，要特别小心，这里藏着陷阱二：整除不等于循环。

判断一个串能否由更短的串重复而成，必须同时满足两个条件：n 能被 p 整除，并且 p 小于 n。为什么第二个条件不能省？当边界为 0 时，p 就等于 n，而 n 除以 n 余数恒为 0。如果只写第一个条件，abcd 这种毫无重复的串也会被判成循环串。

另一方面，第一个条件也不能省，因为 p 不一定整除 n。ababa 的最小周期是 2，但它不是某个串重复若干次。

两个条件缺一不可，代码最后一行把它们用并且连起来。

## P64｜三类上机题怎么落到这组函数上

repetition_count 求最大的重复次数 K：如果是循环串，K 就是 n 除以最小周期；不是循环串时 K 等于 1，相当于串自己重复一次；空串约定返回 0。

这样，三类上机题都能落到这组函数上。循环串，问 s 能否写成更短的串重复至少两次，调用 is_repetition。字符串乘方，问最大的 K，调用 repetition_count。前缀中的周期，要逐个前缀报出 K 大于 1 的那些，做法是对 border 的每个下标 i，把长为 i 加 1 的前缀套用同一个判断。

测试怎么证伪它？独立的参照物就是周期的定义本身：逐个试 p 等于 1、2、3 的 n 的平方量级暴力解。在 a、b 上长度 0 到 10 的全部 2047 个串逐个对拍，C++ 和 Python 各跑一遍。如果改用优化版 next，或者删掉 p 小于 n 这个条件，测试当场变红。

## P66｜本章小结

做个小结，这一章可以归成五点。

第一，串与编码。串是元素限定为字符、操作按整段进行的线性表。char 是字节不是字符；比较按编码单元的字典序；两个裸字面量用小于号比较，比的其实是地址。

第二，变长存储。顺序存放，由类管理缓冲区，长度一变就重新申请、拷贝、释放，追加一个字符是 n 的量级，三法则第三次出场。

第三，接口口径。find 返回可选值，不用负 1；substr 越界抛异常，而不是返回空指针；修改器返回串自身的引用。

第四，朴素匹配。失配右移一位，目标回溯，最坏是两个长度相乘的量级。原书两个匹配算法返回值一律差 1，正确的是 j 减 m。

第五，KMP。next 只依赖模式、可以复用；目标下标只增不减，整体是两个长度相加的量级。求周期要用未优化的 border。

## P69｜T76 最小覆盖子串：题意

先看 T76，最小覆盖子串。给定字符串 s 和 t，返回 s 中涵盖 t 所有字符的最小子串；不存在就返回空串。t 里重复的字符，子串中该字符的数量也不能少于 t 中的数量。

三个示例。示例 1，s 是 ADOBECODEBANC，t 是 ABC，输出 BANC，它包含 A、B、C 各一个，而且找不到更短的。示例 2，s 和 t 都是 a，整个 s 就是答案。示例 3，t 是两个 a，s 里只有一个，无解，输出空串。

进阶要求是 m 加 n 的线性时间。朴素做法枚举所有子串再逐个检查，代价太高。要做到线性，只能让每个字符进出窗口各一次，这就是滑动窗口。

右下角是一个小技巧：s 和 t 只含英文字母，可以直接开一个长 128 的计数数组，用 ASCII 码当下标，比哈希表更快、更省。

## P70｜滑动窗口：右端扩、左端缩

滑动窗口分三个动作。

扩：右端点右移一格，把新字符放进窗口；如果它正是 t 还缺的字符，还缺的总数 required 减 1。

缩：一旦 required 等于 0，说明窗口已经覆盖了 t，就尽量右移左端点。每移出一个字符，如果移出后 t 又缺了它，required 加 1，停下。

记：在每个覆盖状态下，记录最短的窗口。两个端点各最多走 m 步，总共是线性的。

右边讲计数数组的两重身份：大于 0 表示窗口里还缺这么多个；小于 0 表示多了，或者这个字符根本不在 t 中。required 等于所有正值之和，等于 0 当且仅当窗口覆盖 t，于是判断覆盖只要常数时间。

下面是示例 1 的三次覆盖时刻。右端到 5 放进 C，窗口 ADOBEC，长 6；右端到 10 放进 A，左端缩到 5，窗口 CODEBA，也是 6；右端到 12 再放进 C，左端缩到 9，得到 BANC，长度 4，成为最终答案。

## P71｜C++ 实现：need 数组加 required 计数

C++ 实现就是把上一页的三个动作直接写出来。先用 t 填好计数数组，required 初始为 t 的长度。主循环里，右端每放进一个字符，先判断它的计数是否大于 0，是就把 required 减 1，然后计数减 1。当 required 等于 0 时进入内层循环，一边更新最短长度，一边移出左端字符。

右边解释了一个容易写错的顺序：为什么先判大于 0 再减？减之前计数大于 0，说明这个字符正是 t 还缺的，required 才减；不在 t 中的字符，计数会变成负数，不影响 required。收缩时顺序正好反过来：先把计数加回去，再看它是否变成正数，变正了说明 t 又缺它了。

复杂度方面，左右端点各最多走 m 步，时间是 m 加 n 的量级，空间只有 128 个计数。窗口是左闭右开区间，长度就是右端减左端。

## P72｜Python 实现：另一种收缩写法

Python 版用 Counter 计数，收缩的写法略有不同。

和 C++ 版有两点差别。第一，C++ 是在 required 为 0 时一边缩一边记；Python 版先把左侧计数小于 0 的冗余字符全部挤出去，记一次答案，再主动移出左端那个字符，把窗口弄坏，继续寻找下一个可行解。两种写法走的步数其实相同。

第二，Counter 对不存在的键返回 0，所以访问计数之前不必先判断这个字符在不在里面。

还有一个小细节：end 等于 0 表示还没有记过答案。因为窗口长度至少为 1，记过答案以后 end 不可能是 0。

最后看示例 3，s 是 a，t 是两个 a：missing 永远到不了 0，最后返回一个空切片，也就是空串，不需要任何特判。

## P74｜next 与 nextval：改掉了哪三个位置

先把样例模式串的两个数组算出来。BAAABBBAA 的 next 是负 1、0、0、0、0、1、1、1、2；nextval 是负 1、0、0、0、负 1、1、1、0、0。两者只在下标 4、7、8 三个位置不同。

下标 7：p7 是 A，next 是 1，p1 也是 A，相等，所以借用 nextval 的第 1 项，等于 0。

下标 8：p8 是 A，next 是 2，p2 也是 A，同样借用，得 0。其余位置两个字符不等，照抄 next。

右边强调，这和 4.3.2 节是同一个东西：原书的优化版 next 就是这里的 nextval，习题 9 的答案和表中最后一行逐位相同。本题要求先算未优化的 next，再按定义导出 nextval。

## P75｜比较过程追踪：31 次，下标 19

下面逐步追踪，验证 31 和 19。

第一步，主串前 7 个字符和模式前 7 个字符全部相等，累计 7 次。第二步，t7 是 C，p7 是 A，失配，j 退到 nextval 的第 7 项，等于 0，累计 8 次。第三步，C 和 p0 的 B 比，又失配，j 变成负 1，后移不计数，累计 9 次。第四步，t8 到 t16 这 9 个字符依次和 B 比，都不相等，累计 18 次。

第五到第九步，t17 的 B 匹配，t18 的 B 和 p1 的 A 失配，退回 0 后匹配；t19 同样一次失配、一次匹配，累计到 23 次。第十步，t20 到 t27 与 p1 到 p8 的 8 个字符全部匹配，总计 31 次。此时 i 等于 28，j 等于 9，起始位置是 28 减 9，等于 19。

右边对比：如果用未优化的 next，第二步失配后 j 退到 1，要多比一次注定失败的 C 和 A，总共 32 次。nextval 省掉的就是这一次。

## P77｜Python 实现：与 C++ 逐段对应

## P78｜01961 前缀中的周期：题意

第三道题，01961，前缀中的周期。

给定一个长为 N 的字符串 S，对它每个长度至少为 2 的前缀，问它是否由某个子串重复 K 次拼成，K 大于 1。如果是，输出最短循环节对应的 K，也就是所有可能中最大的 K。

输入是多组数据，每组给出 N 和字符串，N 最大到一百万，以单独一个 0 结束。每组先输出编号，然后按前缀长度升序输出长度和 K，每组之后还要输出一个空行，包括最后一组。

看样例。aaa 的长 2 前缀 aa 是 a 重复 2 次，长 3 的 aaa 是 a 重复 3 次。第二组 aabaabaabaab，输出长度 2、6、9、12，对应 K 为 2、2、3、4。

这正是 4.3+ 节三类题里的第三类，对每个前缀套用同一个判断。别忘了，要用未优化的 next，不能用优化版。

---

## P79｜思路：最小周期等于 i 减 nxt

思路分三步。

第一，nxt 的第 i 项，表示长为 i 的前缀的最长相等真前后缀长度，就是 4.3+ 节的 border，一次线性时间算完整个数组，数组长 N 加 1。

第二，由真边界和周期的定理，p 等于 i 减 nxt 的第 i 项，就是这个前缀的最小周期。

第三，判定：nxt 的第 i 项大于 0，并且 i 能被 p 整除，这个前缀就恰由长为 p 的子串重复 K 等于 i 除以 p 次。p 最小，K 自然最大。

为什么大于 0 这个条件不能省？nxt 为 0 时 p 等于 i，而 i 除以 i 恒能整除，没有真边界的前缀，比如 ab，就会被误判成重复 1 次。这就是陷阱二，整除不等于循环。

看样例 2 的表。i 等于 2，nxt 是 1，p 是 1，输出 K 等于 2；从 i 等于 3 开始 p 都是 3，其中长度是 3 的倍数的 6、9、12，分别输出 2、3、4，其余不整除，不输出。

## P80｜C++ 实现：线性求 nxt，线性扫前缀

C++ 实现分两步，都是线性的。先一趟求出 nxt 数组，再一趟扫描所有前缀，按标红的两行判断：算出最小周期 p，如果 nxt 大于 0 且 i 能被 p 整除，就输出 i 和 i 除以 p。每组结束后输出一个空行。

右边讲数据量决定写法。N 可达一百万，所以要关闭输入输出同步，或者改用 scanf 和 printf；nxt 开成全局数组，长度 N 加 1，下标从 0 到 N，避免每组重新申请。求 nxt 那一行把 i 和 k 的自增与赋值写在一起，一行同时推进两个下标，其实和 4.3.2 节的 build_next 是同一个递推，只是不做优化。

复杂度：每组线性时间、线性空间，百万长度也是毫秒级完成。

## P82｜引理：充分性证明

这一页给出最小循环元引理。设串长为 n，next 的第 n 项是整串的最长相等真前后缀长度，L 等于 n 减去它。引理说：如果 n 能被 L 整除，L 就是 S 的最小循环元长度。先证充分性，也就是 L 确实是一个循环节。这一页的下标从 1 开始。

第一步，令 k 为 next 的第 n 项，由定义，长为 k 的前缀等于长为 k 的后缀。第二步，L 等于 n 减 k，这个等式就是：S 从 1 到 n 减 L 这一段，等于从 L 加 1 到 n 这一段。第三步，逐位对应，每个字符都等于它右边第 L 个字符，这正是周期的定义。第四步，循环传导：第 1 个等于第 1 加 L 个，等于第 1 加 2L 个，以此类推。若 n 是 L 的整数倍，整串恰好切成若干块，每块都相同。

右边的例子：abcabcabc，n 等于 9，next 是 6，L 是 3。把前 6 个和后 6 个上下对齐，两行完全相等，也就是每个字符等于它右边第 3 个；9 能被 3 整除，所以是 abc 重复 3 次。

## P83｜最小性证明与不整除的情形

再证最小性，用反证法。

假设存在更短的循环节 L 撇，小于 L。L 撇是循环节，就意味着长为 n 减 L 撇的前缀和后缀相等。而 L 撇小于 L，所以 n 减 L 撇大于 n 减 L，也就是大于 next 的第 n 项。这就找到了一个比 next 更长的相等真前后缀，和 next 是最长的这一定义矛盾。所以 L 最短。

右边补充 n 不能被 L 整除的情形。这时每个字符等于右边第 L 个仍然成立，L 仍是 S 的一个周期，但末尾会剩下一段不足 L 的残缺节，S 不具备完整的循环元，最小循环元长度只能取 n 本身。例子是 ababa：n 等于 5，next 是 3，L 是 2，5 不能被 2 整除，有周期 2，但不是任何串的整数次重复。

总结一句：n 减 next 是串中重复特征的最小偏移量，只要总长能被它整除，对应的前缀就是最小循环元。01961 对每个前缀做的，正是这件事。

## P86｜中心扩展：2n 减 1 个中心

LeetCode 第 5 题，最长回文子串。最常用的做法是中心扩展。

长为 n 的串一共有 2n 减 1 个可能的中心：每个字符本身，以及每两个相邻字符之间。对每个中心向两边扩，直到两端字符不等或越界，记下最长的那一段。

代码里有个巧妙之处：左端取 c 整除 2，右端取 c 加 1 整除 2。c 为偶数时左右相等，中心是一个字符，对应奇数长度的回文；c 为奇数时右端比左端大 1，中心在两字符之间，对应偶数长度。一个循环同时处理了两种回文。

下表比较了四种做法：枚举子串逐个判是 n 的立方，属于反面教材；区间动态规划时间空间都是 n 的平方；中心扩展时间是 n 的平方，空间常数，短而不易错；Manacher 是线性的。

中心扩展浪费在哪里？像全是 a 的串，每个中心都要扩到边，而这些比较大多是在已经确认是回文的区段里重复做的。

## P87｜Manacher：镜像点先给个下限

Manacher 的第一步是在字符之间插入井号，统一奇偶，两端再加两个哨兵。babad 就变成了表中第二行的串。p 的第 i 项是以 i 为中心的回文半径，它恰好等于原串中对应回文的长度。

算法维护目前右端最远的回文，中心 c，右端 r，分三步。

第一，如果 i 落在这个回文内部，它关于 c 的镜像点已经算过，p 的第 i 项至少是 r 减 i 与镜像点半径中较小的那个，直接从这里起步。表里标着镜像的格子都是这样得来的。

第二，向外扩，只比较越过 r 的部分。两个哨兵保证不越界，不用写边界判断。

第三，如果新回文的右端超过了 r，就把 c 和 r 换成它。r 只增不减，每次成功比较都把它推远一格，所以总比较次数是线性的。

看结果：最大半径 3 出现在 i 等于 4，起点是 4 减 3 再整除 2，等于 0，答案是 bab。i 等于 6 先从镜像拿到 1，再扩到 3，对应 aba。

## P88｜manacher：Python 实现与总结

Manacher 的 Python 实现只有一个循环，c 和 r 边走边更新。标红的三行就是上一页的三步：镜像点的答案先拿来用；只有越过 r 的部分才真正比较；右端被推远时更新 c 和 r。最后找出最大半径，把下标换回原串。它和中心扩展在 2000 个随机串上对拍，答案长度全部一致。

为什么要取 r 减 i 与镜像半径中较小的那个？因为镜像点的回文可能伸出 c 的回文左边界之外，那部分在右边并没有被确认过，只能信到 r 为止，剩下的老老实实比。

右边把 KMP 和 Manacher 放在一起：KMP 利用的是前缀等于后缀的平移对称，复用 next 表，目标下标只增不减；Manacher 利用的是左右镜像对称，复用镜像点的半径，最右边界只增不减。两者的线性时间都是摊还出来的。
